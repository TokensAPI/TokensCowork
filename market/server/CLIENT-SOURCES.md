# 新旧客户端来源兼容

市场先按既有组织和 API Key 权限过滤目录，再协商安装来源。能力请求头不是授权凭证。

| 后台来源 | 不声明 tokenscowork 能力 | 声明 tokenscowork 能力 |
| --- | --- | --- |
| npm（兼容来源） | 从公开 npm 查询 latest，返回 npm 安装方式 | 自建仓库配置完整时，从自建仓库查询 latest，返回市场代理安装方式 |
| tokenscowork（仅自建） | 不展示 | 从自建仓库查询 latest，返回市场代理安装方式 |
| GitHub | 保持原行为 | 保持原行为 |

没有配置自建仓库时，兼容来源继续使用公开 npm。配置完整但仓库请求失败时，
不会用公开 npm 的旧版本冒充自建新版，也不会绕过授权；对应条目暂不展示。
后台版本显示及上架检查使用新版的有效来源，但不改写已保存的来源和访问范围。

已有兼容条目不需要重复登记或批量修改数据库。后续同名稳定版本可以仅发布到
自建仓库；旧版继续安装公开 npm 上的版本。仅自建的新插件须在后台选自建来源。
`latest` 仍须指向稳定版本；beta 包可以存在于仓库，但不会作为桌面安装目标。

市场下载代理逐次检查上架状态、插件 ID、包名和访问权限，不将服务账号交给客户端。
自有作用域 @tokensapi/*、@tokens/*、@tokensapi-private/* 及两个既有内置包名
统一限制仓库直连，只允许内部发布账号和市场服务读取。公开/受限切换由 Market
决定，无需重命名包。新插件使用 @tokensapi/*，不要落入公开第三方依赖兜底规则。
公开 npm 历史版本无法收回。第三方依赖继续按 uplink 配置公开回源并缓存。

旧 Pages 域名继续代理市场请求（包括能力头及授权头），不需要重新部署旧桌面。
客户端安装能力由 build/overlays/market 提供，此变更不修改上游子模块或生成安装包。
