## 1. 每次重启需要重新登录

**结论：不能认定所有正常账户登录都会在重启后丢失；找到一个可复现的误注销缺陷和一种明确的临时登录行为。归属 tokens-login。**

- dsh/index.js:387-388 将账户 token 和 user ID 写入 credentials，基础 bundle 使用文件型 credentials-local，具备持久化机制。
- dsh/index.js:578 起的 loginStatus 在启动时读取这两个引用，并在用户信息为空时校验 /api/user/self。
- 使用合成凭据与模拟请求验证：200 + success:true 能恢复 signedIn=true，并保留会话。
- dsh/index.js:329 将任何 success:false 当作会话失效。模拟 429 + success:false，或 200 + success:false 的临时业务失败，均导致 signedIn=false、token 被删除。临时失败不应自动证明 token 失效。
- dsh/client.js:276-278 的启动门禁在支持浏览器登录时只接受 signedIn，不接受单独的 authenticated。手动 API Key 登录在当次提交时放行，但下次启动仅发现已验证 Key 时仍会要求进入。这与按钮“API Key 临时登录”的当前设计一致；若产品希望长期免登录，需调整需求和门禁策略。
- 用户已确认反馈者未说明登录方式；实际反馈尚缺登录方式、重启前后引用是否存在以及 /api/user/self 的响应类别。不要清空用户数据或先归因于 Desktop 存储丢失。

## 2. 英文设置后错误仍有中文

**结论：代码可确认存在语言不一致。至少涉及登录插件和 UI 插件；具体反馈消息仍需对照。**

- 登录插件 dsh/index.js:172、176 等错误为固定中文，如“无法连接 TokensAPI，请检查网络后重试”。
- dsh/index.js:699 返回原始 error.message 和 code，客户端 dsh/client.js:310、366、376、562-563 等直接显示 error，不按 code 映射当前语言。
- 已有中英文普通标签不能覆盖该错误链路。回调网页提示也有固定中文。
- UI 插件 src/client/theme/ThemePicker.tsx 的标题、主题名称、描述、高级选项及玻璃面板提示均为固定中文，没有接入 locale。
- 修复方向：将稳定错误码映射到当前语言；普通 UI 文案接入 locale。不能简单把所有中文替换成英文。

## 3. 微信/WhatsApp 对话框图标重叠

**结论：尚未复现重叠，不标记为已确认 Bug。已定位本机功能提供者。**

- 本机安装的 @tokensapi/dsh-connect 2.9.0 提供微信、WhatsApp 等连接管理界面。
- 安装包 lib/client.js 中，微信 EmptyView6 在约 12846 行，WhatsApp 空状态在约 14022 行；共享布局 .dim-emptyView、.dim-emptyBrand 在约 17326、17330 行；窄容器规则约 17774 行。
- 连接中心导航 ChannelLogo 与 dim-channel 布局也是候选位置。
- 还需确认“对话框”指连接中心、扫码弹窗、聊天侧栏还是工具授权窗口，并记录窗口尺寸、主题、缩放和插件版本。仅凭现有代码不能断言是 Connect 自身布局还是主题样式冲突。

## 4. 市场首页直接显示已安装插件

**结论：当前首页确实不是已安装列表，属于展示/交互需求，不能称为插件安装失效。归属 dsh-community-market 与外层 market 覆盖。**

- 固定 Desktop 的 src/client/MarketSettingsTab.tsx:244 默认 initialView='installable'。
- 市场包含“已安装”页签及 InstalledView，可切换查看。
- 当前首页数据路径加载可安装目录，已安装路径才调用 loadInstallations。
- 可选方向：默认进入已安装、首页增加已安装分区、或目录卡片直接展示安装状态。这三种需求不同，需按产品意图选定。

## 5. 玻璃面板字体模糊

**结论：定位到明确影响清晰度的样式，反馈具有充分代码依据；尚未在反馈者的显示环境做视觉复现。归属 dsh-tokensapi-ui。**

- src/client/theme/chrome.css:1907 起，对开启玻璃面板时的 dialog、选择器、菜单及所有后代统一施加 .1px text-stroke 和 text-shadow !important。
- src/client/theme/themes/clean.css:105 起，浅色文字阴影同时包含亚像素偏移、绿色光晕及最大 10px 模糊阴影，容易形成发光/重影感。
- 这些规则也在实际 staging 的发布客户端中，而非只有未发布源码。
- backdrop-filter 作用于背景，本身不能证明文字被直接 blur；更直接的嫌疑是强制文字描边和多层阴影。
- 建议先保持正文无描边、无发光阴影，再评估是否保留玻璃材质。取消选项只是可选产品决策。

## 6. 点击设置后残留绿框

**结论：候选机制明确，尚未确认反馈是否属于正常焦点提示还是异常残留。归属可能是本体焦点管理与 UI 插件焦点样式的组合。**

- DSH ui-settings-general/src/client/SettingsRoot.tsx:63 打开面板后主动聚焦关闭按钮，:124 关闭后主动恢复设置触发按钮的焦点。这是合理的键盘可访问性行为。
- UI 插件 chrome.css:1696 对所有 button/a/role=button 的 focus-visible 绘制三层绿色 box-shadow。
- 如果绿框围绕当前聚焦按钮，可能是焦点样式；若失焦后仍存在或错位到其他区域，才是残留缺陷。
- 验收需要鼠标打开/关闭、键盘打开/关闭、点击其他区域后的对比；不要为了消除绿框直接移除所有键盘焦点提示。
