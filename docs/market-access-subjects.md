# 插件市场授权名录

## 使用

- API Key 管理：登记 Key，维护名称、备注与逗号分隔的标签，选择可访问的受限插件。
- 组织名录：在组织行点击“插件与标签”，管理本地备注名、标签及插件授权。TokensAPI 同步仍只维护上游组织名称，本地标注不会被覆盖。
- 插件与权限：可搜索已有 Key 名称、标签后直接添加，不必再次粘贴原始 Key。

三个入口使用同一套插件授权关系。标签只帮助搜索和识别，不自动赋权。
公开插件显示为“所有人可访问”，不能在主体页面改变公开范围。取消直接授权不会撤销其他组织/Key 途径的权限，也不会把插件自动公开。
新录入的 Key 仅做格式校验，不代表 TokensAPI 已验证其有效性；真实有效性请使用“授权验证”。

## 兼容与并发

已有直接 Key 授权自动出现在名录中。新旧数据可补充名称和标签，不要求重新录入 Key。
旧版仅 Key 模式的插件，可以继续在 Key 页面管理原授权；要在组织页面分配组织权限，需先在插件页保存组织与 Key 混合权限。界面对此明确禁用并提示，不自动改变旧权限语义。
保存以事务批量提交，同时检查主体和受影响插件的版本；遇到其他管理员修改时返回冲突，刷新后再操作。

## 部署

新增迁移 `006-access-subjects.sql`，自托管服务启动时通过现有迁移加载器执行；先备份市场 SQLite 数据库，再部署并重启服务。
新增管理接口 `/api/admin/subjects`，沿用管理员登录及跨站防护；静态资源新增 `market-subjects.js`。
不需要重建桌面应用，不修改 Nginx，不涉及 npm 仓库配置。
本地另有未发布的版本缓存改动，发布本功能时不得顺带部署未经确认的缓存修改。

Key 原文使用现有 AES-GCM 加密，不放入列表响应、浏览器本地存储或审计日志；加密配置沿用 `MARKET_KEY_ENCRYPTION_SECRET`。
