# TokensCowork v0.5.8

修复网页抓取未接入系统代理，导致部分代理环境中的公网网站被非公网 IP 安全检查拦截的问题。

## 本次更新

- 网页抓取在没有显式代理环境配置时，使用 Electron 按目标 URL 解析的系统代理，并支持隔离 Host 通过 IPC 查询代理路由。
- 保留显式代理优先级、NO_PROXY 和直连请求的地址安全检查，不修改操作系统代理或其他工具的全局网络设置。
- 保留请求取消及超时语义，释放每次抓取创建的代理连接资源。
- 沿用 0.5.7 的 Desktop、DSH 与内置插件固定版本。

## 下载说明

本版本以 pre-release 发布，安装包以 GitHub 构建成功后的附件为准。

- Windows amd64：`TokensCowork-0.5.8-windows-amd64-installer.exe`
- macOS Apple Silicon：`TokensCowork-0.5.8-macos-arm64-installer.dmg`
- macOS Intel：`TokensCowork-0.5.8-macos-amd64-installer.dmg`

## 安装说明

完全退出应用后覆盖安装，无需清理会话、API Key 或插件配置。使用系统 HTTP/HTTPS 代理的用户无需另外设置代理环境变量。

## 验证结果

- Windows 本机系统代理环境：原版抓取 GitHub 与 Hugging Face 均出现 WEB_BLOCKED_URL；修复后均返回 HTTP 200。
- 独立 Electron utilityProcess 经 HostRpc 查询系统代理后，GitHub 抓取返回 HTTP 200；本机回环地址仍被拒绝。
- 63 项外层构建回归通过；注入代理桥接后的 Desktop 主进程 TypeScript 检查零诊断。
- 测试使用隔离进程与临时数据目录，未更改用户系统代理或真实应用数据。

## 已知限制

- macOS 尚未真机验证，需安装预发布后确认；平台构建结果不替代真实代理环境验收。
- 仅支持系统返回的首选 HTTP/HTTPS 代理路由；纯 SOCKS、代理认证及备用代理自动切换不在此次支持范围内。
- 不保证目标网站可访问；网站自身限制、代理故障或 DIRECT 路由下的异常 DNS 仍可能导致抓取失败。
