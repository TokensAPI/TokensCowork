# TokensHarness v0.3.10

本预发布版本上线 TokensAPI 官方插件市场目录源，并修复国内 fake-IP 代理环境下插件市场无法添加该目录源的问题。

## 本次更新

### 新增

- TokensAPI 官方插件目录源上线：在 **设置 → 插件 → 插件市场 → 源** 中添加 `https://tokensharness-market.pages.dev/source.json`，即可浏览本产品全部内置插件的介绍与 GitHub 仓库链接。目录数据由 `product.json` 插件登记自动生成，随产品版本同步更新。

### 修复

- 修复 fake-IP 代理环境无法添加产品插件目录源：常见代理客户端的 fake-IP 模式会把目录源域名解析进保留网段（198.18.0.0/15 及 IPv6 假地址），命中插件市场防 SSRF 网络层的地址封锁，添加来源时报"来源操作失败"。装配阶段为产品目录源主机名加入与上游合作源相同的 fake-IP 豁免，并补齐豁免机制对 IPv6 假地址的处理：豁免主机名仅保留能通过校验的地址，其余主机名维持上游原有的严格拒绝语义。

### 优化

- 移除已停用的 SkillsUI 插件子模块，收敛外层项目的子模块清单。

## 安装说明

### Windows

1. 下载 Windows amd64 安装器并双击运行。
2. 正常升级会自动卸载旧版本并保留 `%APPDATA%\TokensHarness` 用户数据。
3. 如果旧文件仍被占用，先完全退出 TokensHarness 和托盘进程，再重新运行安装器。
4. 未签名安装器可能出现 SmartScreen 提示，请确认文件来自本仓库官方 Release。

### macOS

1. Apple Silicon 用户下载 `arm64`，Intel 用户下载 `amd64`。
2. 打开 DMG，将 TokensHarness 拖入"应用程序"。
3. 未正式公证的构建首次启动时，需要右键应用并选择"打开"。

## 验证重点

1. 开启 fake-IP 代理的环境下，插件市场能成功添加 `https://tokensharness-market.pages.dev/source.json` 并在 Discover 页展示 5 个内置插件卡片。
2. 无代理与普通代理环境下，添加与浏览目录源同样正常。
3. 插件市场对其他用户自加源的地址封锁行为不受影响。
4. 从 v0.3.9 覆盖升级正常，用户数据保留。

## 验证结果

- 装配注入的市场网络层覆盖带锚点守护，上游代码变动时装配失败待人工复查。
- 地址筛选逻辑经 7 场景单元验证（含 fake-IP v4+v6 混合、非豁免域名维持拒绝）；市场 Host 侧 203 个用例全部通过。
- 产品布局、插件依赖许可、Desktop 完整检查和 macOS 双架构构建由本次远程 Action 执行。
- Windows 构建复用最终安装器执行上一稳定版覆盖升级及锁文件恢复 smoke。

## 已知限制

- Windows 安装器暂未进行 Authenticode 签名，可能触发 SmartScreen 提示。
- Windows 文件被其他进程持续占用时，安装器会安全终止，需要关闭占用程序后重试，不会强制结束可能含未保存数据的进程。
- macOS 正式签名与公证取决于仓库是否配置完整的 Apple 发布凭据；否则使用 ad-hoc 签名。
- 目录源域名 `tokensharness-market.pages.dev` 在少数无代理且网络受限的环境下可能不可达；此为网络层限制，后续将评估自定义域名与国内 CDN。
- 当前不提供 Windows ARM64、Windows 32 位或 Linux 安装包。
