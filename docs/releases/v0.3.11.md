# TokensHarness v0.3.11

本预发布版本引入连接中心插件替代单一飞书连接，升级 TokensAPI 模型插件，并修复 Windows 受限沙箱在桌面启动下无法执行命令的问题。

## 本次更新

### 新增

- 连接中心（tokens-connect 2.4.4）随安装包内置，替代原飞书连接插件：统一管理飞书 / Lark、QQ 机器人等外部平台连接，原有飞书应用创建、个人 OAuth、文档与消息工具能力保留。
- 登记 Tokens Cowork UI 0.2.8 与媒体生成插件（本版本均不随安装包分发，验证通过后再启用）。

### 修复

- 修复 Windows 受限沙箱（workspace-write / read-only）在桌面快捷方式启动下所有命令报 0xC0000142 且无输出的问题：桌面为 GUI 进程、没有控制台，而上游 ACL 沙箱要求受限子进程继承宿主控制台。装配阶段为 ACL runner 注入宿主控制台引导——优先连接父终端控制台，无父控制台时创建并立即隐藏，同时恢复原有标准输入输出管道；控制台建立在非受限 runner 进程上，写保护边界不变。
- 新增受限沙箱基础设施熔断：空输出的 0xC0000142 启动失败按会话与沙箱模式熔断，同一会话不再反复真实启动注定失败的进程，并以明确错误提示替代静默循环；danger-full-access 不受影响。

### 优化

- TokensAPI 模型插件升级到 0.2.7：新增隔离回退路由（isolated fallback routing），完善主模型与文本视觉桥接的容错。

## 安装说明

### Windows

1. 下载 Windows amd64 安装器并双击运行。
2. 正常升级会自动卸载旧版本并保留 `%APPDATA%\TokensHarness` 用户数据。
3. 如果旧文件仍被占用，先完全退出 TokensHarness 和托盘进程，再重新运行安装器。
4. 未签名安装器可能出现 SmartScreen 提示，请确认文件来自本仓库官方 Release。

### macOS

1. Apple Silicon 用户下载 `arm64`，Intel 用户下载 `amd64`。
2. 打开 DMG，将 TokensHarness 拖入"应用程序"。
3. 未正式公证的构建首次启动时，需要右键应用并选择"打开"。

## 验证重点

1. 从桌面快捷方式启动 TokensHarness，workspace-write 模式下执行 PowerShell 命令有正常输出，不再出现 0xC0000142；工作区外写入仍被拒绝。
2. 从终端启动时命令执行同样正常，且不弹出多余的黑色控制台窗口。
3. 连接中心插件正常加载，飞书连接能力可用。
4. 插件市场添加 `https://tokensharness-market.pages.dev/source.json` 目录源正常（含 fake-IP 代理环境）。
5. 从 v0.3.10 覆盖升级正常，用户数据保留。

## 验证结果

- ACL 宿主控制台修复经无控制台父进程真实 smoke 验证：受限 PowerShell 输出正常、工作区内写入成功、工作区外写入拒绝（exit 13）。
- 装配注入均带锚点守护，上游代码变动时装配失败待人工复查；Vitest 49 项与产品单元测试全部通过。
- 产品布局、插件依赖许可、Desktop 完整检查和 macOS 双架构构建由本次远程 Action 执行。
- Windows 构建复用最终安装器执行上一稳定版覆盖升级及锁文件恢复 smoke。

## 已知限制

- Windows 安装器暂未进行 Authenticode 签名，可能触发 SmartScreen 提示。
- Windows 文件被其他进程持续占用时，安装器会安全终止，需要关闭占用程序后重试，不会强制结束可能含未保存数据的进程。
- 受限沙箱基础设施熔断为会话级：触发后需重启会话恢复对应受限模式。
- macOS 正式签名与公证取决于仓库是否配置完整的 Apple 发布凭据；否则使用 ad-hoc 签名。
- 当前不提供 Windows ARM64、Windows 32 位或 Linux 安装包。
