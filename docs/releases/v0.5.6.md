# TokensCowork v0.5.6

修复 Claude 模型在 TokensCowork 中被本机安全边界拒绝的问题，恢复 Claude Messages 的正常调用。

## 本次更新

- Claude 模型改为通过 DSH 原生 Anthropic Messages 适配器直连 TokensAPI，不再经过需要 Electron 渲染器能力令牌的本机回环代理。
- 规范 Claude 上游地址并补充 Claude CLI 兼容请求身份，保持模型选择、流式响应和现有 API Key 行为不变。
- 保留 TokensCowork Desktop 的本机 WebServer 安全校验，不通过降低安全边界解决兼容问题。
- 模型管理插件升级至 `0.2.20`，固定提交 `9d5b4975722a9c781e8bbeb4777582212532a7d3`。

附件以上传成功的构建结果为准。

## 安装说明

退出应用后覆盖安装，无需删除用户配置、API Key 或会话数据。

## 验证结果

- 模型管理插件完整串行测试 912 项通过、61 项按环境跳过。
- Claude 与路由相关测试 352 项通过、5 项按环境跳过；TypeScript、Biome Lint、插件构建和版本戳检查通过。
- 使用 TokensCowork 当前捆绑的 `@earendil-works/pi-ai`、Anthropic Messages 和 `claude-opus-5` 完成真实流式传输验证，收到完整 `start → text_start → text_delta → text_end → done` 事件链。
- 新增回归检查，确保生产启动不会再次注册受 Desktop 安全门保护的 Claude 本机代理。
- 安装包及跨平台签名、升级和打包验证以 CI 结果为准。

## 已知限制

- Claude 可用性仍取决于用户网络、TokensAPI 服务状态及对应模型权限；本次修复针对的是请求在本机被错误拒绝的问题。
- 当前真实传输验证覆盖 `claude-opus-5` 的文本流式响应，图片、工具调用及超长上下文仍取决于模型和上游网关能力。
