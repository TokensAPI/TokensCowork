# TokensHarness v0.1.8

本版本修复飞书连接插件在桌面 profile 启动时缺少生产依赖的问题，并重新生成 Windows 与两个 macOS 架构的安装包。

## 本次更新

### 新增

- 默认内置 `@tokens/feishu` 0.1.3，安装 TokensHarness 后即可配置和使用飞书连接能力。
- 飞书连接插件采用 MIT License，并随源码提供完整许可证文本。
- 默认内置 `dsh-tokensapi-ui` 0.1.0，并使用固定 SHA-256 的发布制品参与桌面构建。

### 修复

- 为飞书连接插件声明 Schemastery 直接依赖，以及由桌面宿主提供的 Cordis、命令、凭据和工具 peer 服务。
- 将产品插件 workspace 装配到桌面宿主目录下，使飞书插件的源码导入能够复用宿主唯一的 Cordis、凭据和工具依赖图，修复 macOS 完整 profile 启动失败。
- 将飞书连接插件固定到提交 `028fd7636a33e7a679ad48f7edeb79f7ab2cfbff`，确保运行依赖闭包可审计且可复现。

### 构建

- 产品运行依赖清单与飞书插件 manifest 保持一致，Windows 与两个 macOS 架构使用同一固定依赖图。
- 保持版本更新插件提交 `7d112a198858e140a9bd6f88b56e550059fba605`，并将模型管理插件固定到提交 `c70c01010d4f2eda7ca4870e52f50a9e1c0d37d8`。
- 将 TokensAPI UI 插件固定到提交 `d2e9bf351607105dba65d8348d728768c03ffd35`，发布制品 SHA-256 为 `5b982ed340971f4f8eef860274f598ee16cc9e974c81f30f68c8d1c644ba0f2b`。

## 安装说明

### Windows

1. 下载 Windows amd64 安装器并双击安装。
2. 未签名安装器可能出现 SmartScreen 提示，请确认下载地址来自本仓库 Release。

### macOS

1. Apple Silicon 用户下载 `arm64`，Intel 用户下载 `amd64`。
2. 打开 DMG，将 TokensHarness 拖入“应用程序”。
3. 未签名版本首次启动时需要右键选择“打开”。

## 验证结果

- 发布工作流校验产品版本、固定的子模块提交、运行时闭包、许可证和产品品牌。
- Windows amd64、macOS arm64 与 macOS amd64 使用同一 `0.1.8` 版本和 Git commit 构建。
- macOS 构建执行完整 profile 启动验证，并检查应用架构、代码签名状态与 DMG 完整性。
- 发布成功后统一生成三个安装包的 SHA-256 校验文件。

## 已知限制

- Windows 安装器暂未进行 Authenticode 签名。
- macOS 正式签名与公证取决于仓库是否配置完整的 Apple 发布凭据。
- 当前不提供 Windows ARM64、Windows 32 位或 Linux 安装包。
- 飞书连接功能需要用户自行提供有效的飞书应用配置。
- 模型路由请求 TokensAPI 需要有效的 `TOKENSAPI_API_KEY` 凭据。
