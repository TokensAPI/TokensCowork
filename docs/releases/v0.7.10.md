# TokensCowork v0.7.10

在 v0.7.9 基础上更新「TokensAPI 模型」到 0.2.29：模型列表过滤掉不能用于对话的模型并按厂商排序，正在用的模型下线时自动换回默认模型并提示，新用户默认使用 deepseek-v4-flash-vision-exp。插件市场卡片底部补上「可安装 / 已安装」标签。内核版本与 v0.7.9 相同。

## 本次更新

### ✨ 新增功能

- 正在用的模型被 TokensAPI 下线后自动换回：每次拿到最新模型列表（启动、换 Key、手动刷新）时，若主模型已不在列表里，自动换成默认模型（默认模型也不在时换成列表里第一个可用的对话模型），同步更新内核记住的默认模型，并在设置页顶部和窗口上方提示「模型 A 已下线，已切换为 B」。视觉模型与备用线路模型同样处理。模型列表没拉到（网络断开、服务出错、Key 无效）时绝不更换。以前这种情况下每条消息都会出错，设置页却仍显示原模型。

### 🎨 体验优化

- 模型列表只保留能用于对话的模型：GPT 与 Codex 系列（通过 TokensAPI 上游渠道目前用不了）、向量与重排、语音、生图与生视频、内容审核、StartLux 决策模型不再出现在对话框、设置页和视觉模型候选里。已经选中其中某个模型的，升级后自动换成默认模型并提示「模型 X 在 TokensCowork 中不可用，已切换为 …」。
- 模型列表按厂商分组排序：当前模型排第一，其余按 DeepSeek、Qwen、Kimi、GLM、Gemma、Claude、其他的顺序分组，同一厂商内新版本在前。以前是接口返回的原始顺序，同一厂商的模型分散各处。
- 新用户默认模型改为 deepseek-v4-flash-vision-exp，可直接读图；已经选过模型的用户不受影响。
- 插件市场「发现」页卡片底部标签行加上状态：未安装为绿色「可安装」，已安装为灰色「已安装」，与右上角的「＋ / ✓」对应。

### ⚠️ 其他变更

- 内置插件更新：「TokensAPI 模型」0.2.28 → 0.2.29。其余内置插件与 v0.7.9 相同。
- 产品版本使用 v0.7.10，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### ✨ New Features

- A model TokensAPI retires is replaced automatically: whenever a fresh model list arrives (start-up, a new key, a manual refresh) and the main model is no longer in it, the main model switches to the default (or to the first usable chat model in the list when the default is gone too), the core's saved default moves with it, and a notice at the top of Settings and over the window says "Model A was retired; switched to B". The vision model and the fallback-route model are handled the same way. Nothing changes when the list could not be fetched (network down, service error, invalid key). Previously every message failed in this situation while Settings still showed the old model.

### 🎨 Improvements

- The model list keeps only conversation models: GPT and Codex models (not usable through TokensAPI's upstream channel for now), embedding and rerank, speech, image and video generation, moderation and the StartLux decision model no longer appear in the composer, Settings or the vision candidates. Anyone who had one of them selected is moved to the default on upgrade with the notice "Model X is not available in TokensCowork; switched to …".
- The model list is grouped by maker: the current model first, then DeepSeek, Qwen, Kimi, GLM, Gemma, Claude and the rest, newest version first within each maker. Previously it followed the raw API order, with one maker's models scattered.
- New users default to deepseek-v4-flash-vision-exp, which reads images directly; users who already picked a model are unaffected.
- Cards on the plugin market's Discover page now carry a state tag in their bottom row: a green "Available" before installing and a grey "Installed" after, matching the "+" / "✓" mark in the top-right corner.

### ⚠️ Other Changes

- Built-in plugin updated: "TokensAPI 模型" 0.2.28 to 0.2.29. The other built-ins are unchanged from v0.7.9.
- The product version is v0.7.10 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

"TokensAPI 模型" 0.2.29: the plugin's own suite passes 981 cases; on the real host this product assembles, `check:host` (34) and the host-backed cases (137) all pass, covering "main model retired, then restart: the core default moves and the unknown-model error is gone", the filter and the order; the user started the product with the test script and checked the model list, order, filter and image reading with vision-exp. ## Known Limitations

Same as v0.7.9: downgrading to 0.5.x loses the display of migrated settings and sessions; a failed route save after a model pick reverts the button and logs the reason without a toast; the first open of the market Discover still takes about 1–2 seconds; English release notes in the dialog show highlights but no summary; a very long highlight shows only the whole sentences that fit; session logs are uploaded before each model request, so a turn's last reply is uploaded only with that session's next request. TokensAPI's model list carries no believable release times, so the maker order is fixed in the plugin; once TokensAPI returns real times the list switches to ordering by time on its own. GPT models are hidden by default and can be turned back on with the plugin's `allowGptModels` setting once the upstream channel serves them.
