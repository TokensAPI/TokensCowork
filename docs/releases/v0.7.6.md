# TokensCowork v0.7.6

在 v0.7.5 基础上的体验版：「检查更新」的弹窗现在会告诉你这一版改了什么，不再只有一个版本号；一轮任务执行中的状态行恢复为产品措辞「正在思考中」；设置里的「账户管理」页改用内核自带的设置页结构与组件，与相邻页面一致。内核版本与 v0.7.5 相同。

## 本次更新

### ✨ 新增功能

- 「检查更新」的弹窗带上该版本的发布说明：一段摘要加最多六条要点，并提供「查看完整说明」按钮打开对应版本的发布页。已经是最新版时显示的是已安装版本的说明。取不到正文或正文结构不符时，弹窗与加这段之前逐字相同，检查更新本身不受影响。

### 🐛 问题修复

- 一轮任务执行中的状态行又显示成内核自带的「深度求索中，用时 X」。原因是产品的界面插件按渲染后的文字匹配替换，DSH 0.2.1 改了这两条文案之后不再命中。现在直接改内核的语言表，中英四条一起换成「正在思考中」/「Thinking」，不再依赖渲染结果，上游改动会让构建直接失败而不是悄悄变回内核品牌。
- 设置 →「账户管理」页与相邻设置页不协调：自绘的卡片边框与内边距、过高的 API Key 行、自定义的绿色「当前使用」胶囊，以及一个内核根本没有定义的等宽字体变量（脱敏 Key 一直在用浏览器默认字体）。现在页头、卡片、列表行、按钮与标签全部改用内核自带的设置页结构与组件，颜色字体走主题变量，深色主题自动跟随。登录、注销、切换 Key、复制的逻辑未改。
- 弹窗里的发布说明曾被按字数硬截在半句上（出现过「……只能手动退出再打开。现…」这样的结尾）。现在按句子缩短：先只保留放得下的整句，首句本身超长才退到子句标点并补省略号。
- 弹窗里的英文要点曾被砍得只剩主语。原因是额度按字符个数计，而一个汉字的显示宽度与信息量都约等于两个英文字符。现在额度按显示宽度计（东亚宽字符两列、其余一列），英文每条多显示约九十到一百二十个字符；中文一个字都没少，纯中文的截断点不变，夹有版本号或错误码的中文要点会多显示十几到三十几个字。

### ⚠️ 其他变更

- 内置插件更新：「TokensAPI 账户」0.1.13（账户管理页改版）、「TokensCowork 更新」0.1.7（弹窗里的发布说明与截断）。其余内置插件版本与 v0.7.5 相同。
- 产品版本使用 v0.7.6，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

- 弹窗里的发布说明：对 v0.7.4 与 v0.7.5 两份真实正文逐条比对，v0.7.5 中文逐字不变，v0.7.4 四条中文多显示 10–34 字且旧结果都是新结果的前缀（一个字未少）；英文每条多 88–119 字符，各条宽度均在一行额度内。插件侧 93 项用例、真实内核契约 23/23 通过，变异验证逐条命中预期用例。
- 账户管理页：插件侧用例全绿，真实内核契约 16/16 通过；新增用例锁住"只走主题变量、控件用内核组件"，五种变异各自让对应用例变红。
- 状态行文案与弹窗接线：三条覆盖均以固定的上游源码为输入做用例，真跑注入的方法，锚点漂移各报错一次。
- 完整产品门禁（`build.mjs check`）21 步通过：装配、immutable 安装、运行时补丁、压缩与 RPC smoke、插件编译与裁剪、许可证、Fabric/Market 检查、配置、Desktop 编译、typecheck、closure/CLI/Loader/Profile 校验、品牌门禁，插件真实内核契约（6 个内置 + 4 个市场插件，2 个无 agent 的内置插件按配置豁免，0 失败），以及六个内置插件在同一内核上的功能回归全部通过。覆盖体检 89 条无漂移，构建代码回归 185 项通过。
- 尚未在真实设备上执行 v0.7.6 安装包的安装与上述功能验收（开发态已逐项看过）。

## 已知限制

- 与 v0.7.5 相同：通过 TokensAPI 使用 gpt 系列模型时上游渠道目前只接受 Codex 客户端，发送会失败；Discover 首页的视觉验收尚未完成；降级回 0.5.x 会丢失迁移后的设置与会话显示；切换模型后向路由保存失败时按钮退回原模型并写日志，不弹提示；市场"发现"页首次打开仍需约 1–2 秒。
- 弹窗里的英文发布说明只有要点、没有摘要：产品发布说明的英文半边本来就没有摘要段，且插件以 `## What's New` 为界切分中英两半。要显示英文摘要需同时改模板与切分方式，本版未做。
- 一条很长的要点只显示放得下的整句，其余要用「查看完整说明」查看。
- 插件热更新改到已加载的共享依赖时仍需重启才完全生效，这是内核的限制；市场会提示并提供一键重启。

## What's New

### ✨ New Features

- The update-check dialog now tells you what changed in that version: a short summary plus up to six highlights, with a **View full notes** button that opens the matching release page. When you are already up to date it shows the notes of the installed version. If the notes cannot be fetched or do not match the expected structure, the dialog is word for word what it was before and the update check itself is unaffected.

### 🐛 Bug Fixes

- The running-status line showed the core's own "Deep diving" wording again. The product's UI plugin replaced that text by matching the rendered string, and DSH 0.2.1 reworded it, so the match stopped firing. The core's locale table is now changed directly — all four strings, Chinese and English, become "正在思考中" / "Thinking" — so it no longer depends on the rendered output, and an upstream rewording fails the build instead of silently restoring the core's brand.
- Settings → Account did not match the settings pages next to it: hand-drawn card borders and padding, over-tall API key rows, a custom green "in use" pill, and a monospace font variable the core never defines (the masked key had been falling back to the browser default). The page header, cards, list rows, buttons and tags now use the core's own settings structure and components, colours and fonts come from theme variables, and dark mode follows the core automatically. Sign-in, sign-out, key switching and copying are unchanged.
- Release notes in the dialog were cut by character count, which left highlights ending mid-sentence. They are now shortened at sentence boundaries: whole sentences first, and only an over-long first sentence falls back to a clause boundary with an ellipsis.
- English highlights in the dialog were cut down to little more than the subject, because the budget counted characters while a Chinese character is about twice as wide and carries about twice as much. The budget is now measured in display columns, so each English highlight shows roughly 88–119 more characters. No Chinese text was lost: pure Chinese cuts at exactly the same point, and Chinese highlights containing version numbers or error codes show 10–34 more characters.

### ⚠️ Other Changes

- Built-in plugins updated: "TokensAPI Account" 0.1.13 (account page restyle) and "TokensCowork Updates" 0.1.7 (release notes in the dialog and the shortening). The other built-ins are unchanged from v0.7.5.
- The product version is v0.7.6 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Release notes in the dialog: the real v0.7.4 and v0.7.5 bodies were compared highlight by highlight — v0.7.5 Chinese is identical word for word, four v0.7.4 Chinese highlights show 10–34 more characters with the old output a prefix of the new one (nothing lost), and each English highlight shows 88–119 more characters within one line budget. The plugin passed 93 cases and 23/23 real-core contracts, with mutation checks hitting exactly the expected cases. Account page: the plugin's own suite passed with 16/16 real-core contracts, new cases lock down "theme variables only, core components only", and five mutations each turn the matching case red. Status-line copy and the dialog wiring: all three overlays are tested against the pinned upstream sources, the injected method is executed for real, and a drifted anchor raises once per overlay. The full product gate (`build.mjs check`) passed all 21 steps: assembly, immutable install, runtime patches, compaction and RPC smoke, plugin compilation and pruning, licenses, Fabric/Market checks, configuration, Desktop build, typecheck, closure/CLI/Loader/Profile verification, the branding gate, the plugin real-core contracts (6 built-in and 4 market plugins, the 2 agent-less built-ins exempt by configuration, none failed) and the built-in plugin regression against that same core. Overlay doctor reported 89 overlays with no drift and the build-code regression passed 185 cases. Installation and functional acceptance of the v0.7.6 installers on real devices have not been performed yet, though every change above was checked in a development build.

## Known Limitations

Same as v0.7.5: GPT models via TokensAPI currently fail to send because the upstream channel only accepts the Codex client; visual acceptance of the Discover home is pending; downgrading to 0.5.x loses the display of migrated settings and sessions; a failed route save after a model pick reverts the button and logs the reason without a toast; the first open of the market Discover still takes about 1–2 seconds. The English release notes in the dialog show highlights but no summary: the English half of our release notes has no summary paragraph and the plugin splits the two languages at `## What's New`, so showing one needs both a template change and a change to that split; it is not in this version. A very long highlight shows only the whole sentences that fit, and **View full notes** opens the rest. A plugin hot update that replaces already-loaded shared dependencies still needs a restart to take full effect, which is a core limitation; the market says so and offers a one-click restart.
