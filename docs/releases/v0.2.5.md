# TokensHarness v0.2.5

本版本作为桌面端预发布候选，更新 TokensAPI 模型管理插件的协议、多模态能力与当前会话切换策略。请先完成文本视觉桥接与原生多模态模型的真机切换验证，再决定是否提升为正式版本。

## 本次更新

### TokensAPI 模型管理 0.2.0

- 默认内置 `@tokens/dsh-model-manager` 0.2.0，固定到提交 `738e097e375ed9c0b6e06492d101b775434d0f8d`。
- 保留 TokensAPI 模型列表返回的协议能力，并按模型选择 `anthropic-messages`、`openai-responses` 或 `openai-completions`。
- Claude 等已确认的原生多模态模型声明文本与图片输入，Desktop 不再提前拒绝图片。
- DeepSeek、GLM 文本模型继续使用“主文本模型 + 视觉模型”桥接，原生多模态模型则直接读取图片。
- 保存模型后等待 DSH 模型目录刷新，再切换当前会话，避免 `UNKNOWN_MODEL` 和会话仍停留在旧模型。
- 模型目录短暂刷新失败会重试；目标模型始终未出现时显示明确错误，不再报告虚假成功。

### 发布流程

- 外层项目继续只使用 `master`，不增加 `dev` 分支。
- 手动运行 Desktop 发布工作流时可以勾选 `prerelease`，GitHub Release 将标记为 Pre-release，不会取代稳定版 `latest`。

## 安装说明

### Windows

1. 下载 Windows amd64 安装器并双击安装。
2. 未签名安装器可能出现 SmartScreen 提示，请确认文件来自本仓库 Pre-release。
3. 启动 TokensHarness，根据全屏提示验证 TokensAPI API Key。
4. 进入“设置 → 模型”完成文本视觉组合与原生多模态模型切换测试。

### macOS

1. Apple Silicon 用户下载 `arm64`，Intel 用户下载 `amd64`。
2. 打开 DMG，将 TokensHarness 拖入“应用程序”。
3. 未正式公证的构建首次启动时，需要右键应用并选择“打开”。
4. 启动后验证 TokensAPI API Key，再执行同样的模型与图片测试。

## 建议验证

1. 使用 DeepSeek 文本模型和独立视觉模型上传图片，确认桥接回答正常。
2. 在同一会话切换到 `claude-opus-4-7`，确认模型选择同步且允许直接上传图片。
3. 确认 Claude 请求不再出现 `Input tag 'function'`，切换模型不再出现 `UNKNOWN_MODEL`。
4. 从原生多模态模型切回文本视觉组合，确认当前会话和新会话行为一致。

## 验证结果

- 插件模型管理、Desktop 客户端与版本固定相关测试共 152 条，全部通过。
- 插件 lint、TypeScript 类型检查与生产构建全部通过。
- 全仓测试共 787 条通过；6 条 Windows 符号链接用例因系统未授予创建链接权限返回 `EPERM`，与本次模型策略无关。
- 产品版本元数据、发布说明、插件固定提交与子模块提交由外层发布前检查验证。

## 已知限制

- 本版本仍需要 TokensHarness Desktop 真机验证后再提升为正式版本。
- Windows 安装器暂未进行 Authenticode 签名。
- macOS 正式签名与公证取决于仓库是否配置完整的 Apple 发布凭据；否则使用 ad-hoc 签名。
- 当前不提供 Windows ARM64、Windows 32 位或 Linux 安装包。
