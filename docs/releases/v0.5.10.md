# TokensCowork v0.5.10

改进 Claude、GPT 与 Codex 的模型调用和切换体验，加快插件市场与联网搜索，修复系统代理下的网页抓取和应用内更新下载，并新增工具调用循环护栏。

## 本次更新

### ✨ 新增功能

- 内置工具调用循环护栏：识别相同参数和命令骨架相近的重复调用，达到阈值后提供提醒或纠正反馈，减少模型反复执行相同操作。
- 会话模型选择器展示所有可用对话模型，跨协议切换时自动匹配并同步当前会话。

### 🐛 问题修复

- 修复应用内更新安装包经过文本型跨进程桥接后数据异常的问题，改用二进制下载并保留 SHA-256 校验。
- 修复更新下载或安装器启动失败时静默失败、误报成功的问题，明确返回失败状态并提示重试。
- 修复 Claude 请求被本机安全边界或错误请求身份拒绝的问题，在最终出网边界设置所需身份，并保留路径隔离及 Desktop 安全检查。
- 修复系统代理环境中网页抓取未接入代理、被地址安全检查拦截的问题；显式代理和 NO_PROXY 优先规则保持不变。
- 修复发布版本与生成市场清单不同步导致的构建失败，版本同步时自动生成并校验清单。
- 统一 Windows 快捷方式、原生终端、启动恢复与插件市场中的产品品牌文案。

### 🎨 体验优化

- 插件市场先显示本地已安装列表，再后台检查更新；检查失败仍保留列表并可重试，复用有效目录版本提示以减少重复查询。
- 联网搜索改用引擎竞速：首选引擎正常响应时只发出一次请求；挂起或失败时由其他免费引擎接管，付费或需密钥引擎仍串行兜底。
- 模型按家族选择协议，兼容新增型号与供应商命名空间；保存非默认协议前进行流式验证，临时服务或网络失败不覆盖原配置。
- 内置 UI 插件更新至 0.2.22，改善隔离运行时适配、长问题展示与回合状态文案。

### ⚠️ 其他变更

- 此说明汇总 v0.5.1 之后至 v0.5.10 的变化，包含中间候选版本的修复，合并了重复条目；不包含 v0.5.10 之后的功能。
- Claude 默认采用 Anthropic Messages，GPT/Codex 默认采用 Responses，其他模型优先恢复已保存协议，否则使用 Chat Completions。纯语音等非对话模型不会出现在会话模型列表中。
- 启用产品循环护栏时停用上游重复调用提醒，避免同一操作收到双重提醒。

### Windows

1. 下载 Windows amd64 安装器，完全退出正在运行的 TokensCowork。
2. 双击安装器，按提示完成安装。
3. 签名及系统提示：签名状态以该版本构建记录为准；若出现 SmartScreen 提示，请先核对下载来源为本仓库 Release。

- 数据与配置保留情况：完全退出应用后覆盖安装，保留原有配置与会话，无需删除用户数据。
- 需要执行的迁移或兼容性操作：无需手动迁移。旧版应用内更新若失败，请从此 Release 手动下载安装包；新修复不会自动改变旧版下载逻辑。
- 插件升级、重启或重新授权要求：安装后重新启动以加载更新的内置插件；模型协议配置与调用能力仍受上游模型和服务支持情况影响。

## 已知限制

- 网络权限、代理及远程服务故障仍可能导致更新下载或模型请求失败。
- 系统代理网页抓取仅支持首选 HTTP/HTTPS 路由，纯 SOCKS、代理认证和备用代理自动切换不在支持范围内。
- 循环护栏检查工具调用，纠正反馈发生在工具执行后，不能撤销已执行操作，也不能保证终止模型单条回答中的文字循环。
- 跨平台真实覆盖安装、应用内更新及所有模型能力尚未全面验收；稳定版状态不等于所有场景均已验证。

## What's New

Improve Claude, GPT and Codex requests and model switching, speed up the plugin market and web search, fix web fetching through system proxies and in-app update downloads, and add a repeated-tool-call guard.

### ✨ New Features

- Bundle a repeated-tool-call guard that detects identical arguments and similar command shapes, then provides reminders or corrective feedback at configured thresholds.
- Show all available conversational models in the session selector and apply the appropriate protocol when switching models.

### 🐛 Bug Fixes

- Fix installer corruption caused by sending binary update downloads through a text-only cross-process bridge. Download binary data directly and retain SHA-256 verification.
- Report update-download and installer-launch failures clearly instead of failing silently or reporting success.
- Fix Claude requests rejected by local security boundaries or incorrect request identity, applying the required identity at the outbound boundary while preserving path isolation and Desktop security checks.
- Route web fetching through the system proxy when no explicit proxy is configured, preserving explicit-proxy precedence and NO_PROXY rules.
- Generate and verify market manifests during version synchronization to prevent release builds failing on stale metadata.
- Use consistent product branding in Windows shortcuts, native terminals, startup recovery and the plugin market.

### 🎨 Improvements

- Show local installed plugins before checking updates in the background. Keep the list usable after network failures and reuse valid catalog hints to reduce repeated queries.
- Race free web-search engines when the preferred engine stalls or fails. A normal preferred-engine response still uses one request; paid or key-based engines remain sequential fallbacks.
- Select protocols by model family, supporting new variants and provider namespaces. Validate streaming responses before saving non-default protocols and preserve existing settings on temporary service or network failures.
- Update the bundled UI plugin to 0.2.22 for isolated-runtime compatibility, longer questions and clearer turn-status text.

### ⚠️ Other Changes

- These notes consolidate changes after v0.5.1 through v0.5.10, including fixes from intermediate candidates, with duplicate entries merged. They exclude changes introduced after v0.5.10.
- Claude defaults to Anthropic Messages and GPT/Codex to Responses. Other models restore a saved protocol or default to Chat Completions. Non-conversational models are excluded from the session selector.
- Disable the upstream repeat-call reminder when the product loop guard is enabled to avoid duplicate reminders.

### Bundled Components and Plugins

|---|---|---|
| Desktop / DSH runtime | 0.1.5-rc.2 | Unchanged source/runtime pins; product overlays fix proxy routing, branding and manifest synchronization |
| @tokens/dsh-version-updates | 0.1.0 | Binary download and failure reporting fixes |
| dsh-tokensapi-ui | 0.2.22 | Runtime compatibility, longer questions and status text |
| @tokens/dsh-model-manager | 0.2.21 | Claude request compatibility and cross-protocol switching |

1. Download the Windows amd64 installer and fully quit TokensCowork.
2. Run the installer and follow its instructions.
3. Signing status and system prompts: Refer to the build records for signing status. If SmartScreen appears, verify that the installer came from this repository’s release.

1. Check your processor in About This Mac and select the Apple Silicon or Intel installer.

3. First launch, signing and notarization: Refer to the build records for signing and notarization status. If macOS blocks launch, verify the source before using the system’s Open action.

### Upgrading from an Earlier Version

- Data and configuration retention: Fully quit the application before installing over the existing version. Keep existing configuration and sessions; deleting user data is unnecessary.
- Required migration or compatibility steps: No manual migration is required. If an older version cannot download an update, install manually from this release; the fix does not alter the downloader in the older application.
- Plugin updates, restarts or reauthorization: Restart after installation to load updated bundled plugins. Protocol availability and model capabilities still depend on upstream models and services.

## Known Limitations

- Network permissions, proxies and remote-service failures can still interrupt update downloads or model requests.
- System-proxy web fetching supports the preferred HTTP/HTTPS route; SOCKS-only proxies, proxy authentication and automatic fallback routing are unsupported.
- The loop guard checks tool calls after execution. It does not undo completed operations or guarantee termination of repetitive text within a single model response.
- Real cross-platform upgrades, in-app updates and all model capabilities have not been exhaustively verified. Stable-release status does not imply validation of every scenario.
