# TokensCowork v0.4.1

修复升级新运行时后模型对话在受管路由上首条消息即失败的问题，并默认启用插件市场。

## 本次更新

### 关键修复

- 修复 v0.4.0 对话报错 `registration.adapter.prepareCall is not a function`：新运行时为模型适配器契约新增 `prepareCall`，TokensAPI 模型插件的 modlens 视觉包装器未跟上该契约，导致经其合成路由的对话全部失败。模型插件升级到 0.2.15（4cb8d2d5），按新契约补齐并附回归测试。

### 功能变化

- 插件市场默认启用：产品跳过上游首次设置向导后，市场提供方一直停留在上游默认的“关闭”，新装用户看不到插件市场。现无显式选择时默认启用社区市场；用户在设置中的显式选择（包括关闭）与 Safe Mode 行为保持不变。
- Tokens Cowork UI 升级到 0.2.18，与远端发布产物一致。
- 移除内置“按路径引用文件”插件（tokens-at-file），产品清单、市场名册与依赖锁同步删除。
- 桌面标题栏与设置页的可见名称统一为产品品牌，品牌门禁同步校验编译产物。

### 构建与开发

- 插件产物拉取增加目录级校验标记与瞬态错误重试，重复装配更快、Windows 上更稳。
- 开发启动脚本自动判断装配与构建时机，并完整构建市场插件宿主模块（此前缺失，市场默认启用后启动即报模块缺失）。

## 安装说明

### Windows

1. 下载 Windows amd64 安装器并双击运行。
2. 覆盖安装会保留 TokensCowork 用户数据、插件配置与市场安装记录。
3. 未签名安装器可能出现 SmartScreen 提示，请确认文件来自本仓库官方 Release。

### macOS

1. Apple Silicon 用户下载 `arm64`，Intel 用户下载 `amd64`。
2. 打开 DMG，将 TokensCowork 拖入“应用程序”。
3. 未正式公证的构建首次启动时，需要右键应用并选择“打开”。

## 验证结果

- 模型插件回归测试通过：`prepareCall` 按宿主调用路径解析 modlens 路由模型并委托真实上游；套件失败集与修复前基线完全一致（仅既有的 Windows 符号链接权限用例）。
- 沙箱全新首启验证：市场提供方落盘为社区市场，预置 TokensAPI 目录源默认选中；市场宿主模块随开发构建产出并可加载。
- 产品布局、版本钉定、市场名册一致性与快照闸门全部通过（5 个内置插件子模块、8 项市场目录）。
- 完整的桌面与市场测试套件、运行时闭包与许可证门禁由发布流水线在构建各平台安装包前执行，未全部通过不会发布。

## 已知限制

- 已在 v0.4.0 下启动过的现有安装此前被记录为“市场关闭”，且无法与用户显式关闭区分，升级后不会自动翻转；可在设置中手动启用插件市场。
- Windows 安装器暂未进行 Authenticode 签名，可能触发 SmartScreen 提示。
- macOS 正式签名与公证取决于仓库是否配置完整的 Apple 发布凭据；否则使用 ad-hoc 签名。
- 当前不提供 Windows ARM64、Windows 32 位或 Linux 安装包。
