# TokensCowork v0.7.8

在 v0.7.7 基础上新增内置插件「会话日志上传」：使用 TokensAPI 对话时，把会话日志在后台上传到 TokensCowork 的服务，用于改进模型与产品，可在设置中关闭。侧栏不再显示重复的「插件」入口。内核版本与 v0.7.7 相同。

## 本次更新

### ✨ 新增功能

- 新增内置插件「会话日志上传」：会话每发起一次模型请求，插件就在后台把这个会话新增的事件发一批到 `https://market.tokensapi.ai/v1/session-logs`，时机与上游 DeepSeek 官方 API 的 Session Log 相同。上传与模型请求完全分开：服务不可用、超时或被拒绝都只影响上传本身，对话照常完成，界面不报错，下一次请求再带上没传成功的部分。上传内容是会话的原始记录，包括对话内容、模型的思考与回答、工具调用与结果、所用模型与用量，不做脱敏；请求带当前的 TokensAPI Key 用于识别来源。只上传装上本版本后仍在对话的会话，不补传以前的会话。上传地址写在插件里，不能通过本地配置修改。

### 🎨 体验优化

- 设置 → 通用设置里原来的「在使用官方模型 API 时上传 Session Log」换成「在使用 TokensAPI 时上传 Session Log」，默认开启，关闭后不再上传，重新打开后下一次请求会补上关闭期间的内容。上游那一行只对 DeepSeek 官方 API 生效，产品走 TokensAPI 时本来就不起作用，现已停用。
- 侧栏不再显示「插件」入口：插件统一在侧栏底部的「插件市场」管理。插件页本身仍在，设置里的「前往插件页」和跳到某个插件详情照常可用。

### ⚠️ 其他变更

- 内置插件新增：「会话日志上传」0.1.1。其余内置插件与 v0.7.7 相同。
- 插件市场服务新增会话日志的接收、存储与后台查看（只有平台管理员可见，查看会话详情会写操作记录），已随本版本之前部署上线。
- 产品版本使用 v0.7.8，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

- 与 v0.7.7 相同：通过 TokensAPI 使用 gpt 系列模型时上游渠道目前只接受 Codex 客户端，发送会失败；Discover 首页的视觉验收尚未完成；降级回 0.5.x 会丢失迁移后的设置与会话显示；切换模型后向路由保存失败时按钮退回原模型并写日志，不弹提示；市场"发现"页首次打开仍需约 1–2 秒；弹窗里的英文发布说明只有要点没有摘要；很长的要点只显示放得下的整句。

## What's New

### ✨ New Features

- New built-in plugin "Session Log Upload": every time a session sends a model request, the plugin uploads that session's new events in the background as one batch to `https://market.tokensapi.ai/v1/session-logs`, on the same schedule as the upstream Session Log for the official DeepSeek API. Uploading is fully separate from model requests: an unavailable service, a timeout or a rejection only affects the upload, the conversation completes as usual with no error shown, and whatever was not uploaded goes out with the next request. The upload is the raw session record, including the conversation, the model's reasoning and replies, tool calls and results, and the models and usage involved, without redaction; requests carry the current TokensAPI key to identify the source. Only sessions still in use after installing this version are uploaded; earlier sessions are not backfilled. The upload address is built into the plugin and cannot be changed through local configuration.

### 🎨 Improvements

- In Settings → General, "Upload Session Log when using the official model API" is replaced by "Upload Session Log when using TokensAPI", on by default. Turning it off stops uploads, and turning it back on sends what was missed with the next request. The upstream row only applied to the official DeepSeek API and never took effect with TokensAPI, so it is now disabled.
- The sidebar no longer shows a "Plugins" entry; plugins are managed from "Plugin Market" at the bottom of the sidebar. The plugins page itself remains, and "Go to plugins" in settings and links to a plugin's details still work.

### ⚠️ Other Changes

- Built-in plugin added: "Session Log Upload" 0.1.1. The other built-ins are unchanged from v0.7.7.
- The plugin market service now receives, stores and displays session logs (visible to platform administrators only; opening a session's details is recorded in the activity log). It was deployed before this release.
- The product version is v0.7.8 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Session Log Upload: the plugin's own suite passes; on the host this product assembles, real conversations complete normally with no host errors while the upload service returns 500, hangs or returns invalid data; the product was started with the test script and uploaded to a local backend, where the session, version, key and events arrived intact. Session log service: the receiving endpoint is deployed on market.tokensapi.ai, and live checks (a small batch, a repeated batch and a 1.5 MiB compressed batch) all returned 200. The CI Windows quality gate passed in full (assembly, dependency install, runtime and compaction smoke tests, plugin compilation, type checks, branding checks, plugin real-host contracts and built-in plugin regression), build run 41383387532. Installation and interface acceptance of the v0.7.8 installers on real devices have not been performed yet.

## Known Limitations

Same as v0.7.7: GPT models via TokensAPI currently fail to send because the upstream channel only accepts the Codex client; visual acceptance of the Discover home is pending; downgrading to 0.5.x loses the display of migrated settings and sessions; a failed route save after a model pick reverts the button and logs the reason without a toast; the first open of the market Discover still takes about 1–2 seconds; English release notes in the dialog show highlights but no summary; a very long highlight shows only the whole sentences that fit. Session logs are uploaded before each model request, as upstream does, so the last reply of a turn is uploaded only with that session's next request, and the last reply of a session that is never reopened is not uploaded. A failed upload is not retried on its own; it goes out with the next request.
