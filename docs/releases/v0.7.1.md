# TokensCowork v0.7.1

在 v0.7.0 基础上的修正版：侧栏"插件"页只保留 TokensCowork 自己的插件市场，不再显示上游的 dsh-market、来源配置与远程控制入口；修复"TokensCowork 更新"插件在 DSH 0.2 内核上侧栏下载按钮渲染即崩的问题。内核版本与 v0.7.0 相同。

## 本次更新

### 🐛 问题修复

- 侧栏"插件"页：Desktop 2.0.18 新版插件页会把上游的 dsh-market 与产品市场并排显示，并提供"来源配置"弹窗和"启用插件市场"开关，用户可以切到其他市场或把市场关掉（重启后又被产品改回）。现在只显示 TokensCowork 插件市场一张卡，去掉其他市场、来源配置与开关；同页的"远程控制"卡也不再显示（与侧栏入口一致，随包携带但不露出）。
- "TokensCowork 更新"插件升到 0.1.2：DSH 0.2 内核把图标组件改了名，0.1.1 的侧栏下载按钮在检查到可用更新时渲染即崩（v0.6.0、v0.6.1、v0.7.0 都受影响，表现为左下角没有下载按钮）；0.1.2 改用新图标，并新增"客户端导入与内核真实导出逐名核对"的用例防止再犯。

### ⚠️ 其他变更

- "TokensCowork 更新"插件不再依赖上游已停发的 `@deepseek-ai/dsh-invariants`，产品随之去掉为它保留的兜底版本；运行时依赖只剩 `@deepseek-ai/dsh-atomic-write` 与 `@deepseek-ai/schemastery`。
- 产品版本使用 v0.7.1，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### 🐛 Bug Fixes

- Sidebar Plugins page: the Desktop 2.0.18 page lists the upstream dsh-market next to the product market and offers a "Source configuration" dialog and an "Enable plugin market" switch, so users could switch to another market or turn the market off (only to have the product restore it on restart). The page now shows the TokensCowork plugin market only, without other markets, source configuration or the switch; the "Remote Control" card on the same page is hidden as well (bundled but not exposed, consistent with the sidebar entry).
- "TokensCowork Updates" plugin updated to 0.1.2: the DSH 0.2 core renamed an icon component, so 0.1.1's sidebar download button crashed as soon as an update was available (v0.6.0, v0.6.1 and v0.7.0 were affected — the button was simply missing); 0.1.2 uses the new icon and adds a test that checks every client import against the core's real exports.

### ⚠️ Other Changes

- The "TokensCowork Updates" plugin no longer depends on the discontinued `@deepseek-ai/dsh-invariants`; the product drops the fallback it kept for that package, leaving `@deepseek-ai/dsh-atomic-write` and `@deepseek-ai/schemastery` as its runtime dependencies.
- The product version is v0.7.1 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

The Plugins page is narrowed by three product overlays (single market card, hidden remote control, hidden official custom-market entry) whose anchors fail the build when they drift; the overlay doctor reports 63 overlays effective, none broken, none obsolete; the market overlay tests (40) and the build-code regression (154) passed, and on the staged tree all five Desktop tsconfig typechecks and 4 related vitest suites (75 cases) passed. Updates plugin 0.1.2 passed 83/83 cases on each of 0.2.1-rc.2, 0.2.0-rc.2 and the fixed upstream fixture; after the pin bump the overlay doctor reports all 60 executable overlays effective and the build-code regression passed 144 cases. The full product gate (`build.mjs check`) passed all 19 steps (assembly, immutable install, runtime patches, compaction and RPC smoke, plugin compilation and pruning, licenses, Fabric/Market checks, configuration, Desktop build, typecheck, closure/CLI/Loader/Profile verification, branding gate). The release pipeline is unchanged from v0.7.0 and was not rehearsed separately; installer sizes are those on the release page. Installation and Plugins-page acceptance of the v0.7.1 installers on real devices have not been performed yet.

## Known Limitations

Same as v0.7.0: GPT models via TokensAPI currently fail to send because the upstream channel only accepts the Codex client; the market's uninstall-then-install update has not been verified on a real device; visual acceptance of the Discover home is pending; downgrading to 0.5.x loses the display of migrated settings and sessions.
