## 本次更新

### 🐛 问题修复

- 修复长会话中模型只输出几百个甚至 1 个 token 就提示「已达到输出 token 上限」，发送「继续」后仍立即截断、无法恢复的问题。原因是通过 TokensAPI 调用模型时，应用会按估算的对话长度压低单次输出上限，而估算把以前所有的思考内容都算了进去，思考较多的长会话里估算值远大于实际长度，输出上限被压到接近 0。现在拿不到服务端统计的实际用量时，直接使用模型配置的输出上限，上下文接近上限时仍由自动压缩处理。
- 修复在启动登录页登录后，左下角仍显示「更多」、不显示用户名，需要打开设置或重启才更新的问题（TokensAPI 账户 0.1.14）。

### ⚠️ 其他变更

- 产品版本使用 v0.7.19，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### 🐛 Bug Fixes

- Fixed long conversations in which the model stopped after a few hundred tokens, or even one, with "Output token limit reached", and sending "continue" was cut off again every time. When calling models through TokensAPI, the app lowers each request's output limit by an estimate of the conversation length, and that estimate counted every earlier reasoning block. In long conversations with a lot of reasoning the estimate far exceeded the real length and pushed the output limit close to zero. When the server-reported usage is not available, the app now sends the model's configured output limit; a nearly full context is still handled by automatic compaction.
- Fixed the bottom-left account entry still showing "More" instead of the user name after signing in on the startup sign-in page, until Settings was opened or the app restarted (TokensAPI Account 0.1.14).

### ⚠️ Other Changes

- The product version is v0.7.19 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Output limit: the request at the point of failure was rebuilt from a user's exported conversation (338 messages, 37 images) and sent to TokensAPI through the model integration code the app uses. Before the fix the request carried an output limit of 1 and the model stopped on length after one token, matching the user's log; after the fix the limit was 32768 and the model answered normally. Five build-code regression tests were added. TokensAPI Account 0.1.14: plugin CI passed on Node 22 and 24; 85 plugin regression cases and 16 real-host contract tests passed; new cases cover both browser sign-in and a manually entered API key. The overlay registry check found no drift and build-code regression passed 239 tests. Installation and interface acceptance of the v0.7.19 installers on real devices have not been performed yet.

## Known Limitations

Same as v0.7.18: downgrading to 0.5.x loses the display of migrated settings and sessions; session logs are uploaded before each model request, so a turn's last reply is uploaded only with that session's next request; GPT and Codex models are not usable through TokensAPI for now and are hidden from the model list by default.
