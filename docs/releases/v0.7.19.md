# TokensCowork v0.7.19

在 v0.7.16 基础上，修复四个问题：长会话中「已达到输出 token 上限」反复截断、插件市场更新插件卡住、图片识别偶发失败、登录后左下角不显示用户名。本说明汇总 v0.7.17 至 v0.7.19 的全部改动。

## 本次更新

### 🐛 问题修复

- 修复长会话中模型只输出几百个甚至 1 个 token 就提示「已达到输出 token 上限」，发送「继续」后仍立即截断、无法恢复的问题。原因是通过 TokensAPI 调用模型时，应用会按估算的对话长度压低单次输出上限，而估算把以前所有的思考内容都算了进去，思考较多的长会话里估算值远大于实际长度，输出上限被压到接近 0。现在拿不到服务端统计的实际用量时，直接使用模型配置的输出上限，上下文接近上限时仍由自动压缩处理。
- 修复在插件市场更新或卸载插件时，界面可能停在「正在更新…」约 10 分钟、什么都点不了，结束后提示失败，重新打开应用后插件变成「可安装」的问题。原因是应用内置的 pnpm 11.8.0 有一个已知缺陷：完成安装或卸载后，进程偶尔不会退出。现在内置的 pnpm 升级到 11.28.5，Windows 和 macOS 都已修复。
- 主模型通过视觉模型读图时，如果识别失败（例如网络抖动或上游临时出错），现在会自动重试 2 次，不再一次失败就整轮提示「图片识别失败」；失败结果也不再保留 60 秒，重新发送会立刻重新识别（TokensAPI 模型 0.2.31）。
- 修复在启动登录页登录后，左下角仍显示「更多」、不显示用户名，需要打开设置或重启才更新的问题（TokensAPI 账户 0.1.14）。

### ⚠️ 其他变更

- 内置 pnpm 升级后第一次安装插件时，会重新下载一次插件的元数据缓存，速度可能比平时稍慢。
- 产品版本使用 v0.7.19；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### 🐛 Bug Fixes

- Fixed long conversations in which the model stopped after a few hundred tokens, or even one, with "Output token limit reached", and sending "continue" was cut off again every time. When calling models through TokensAPI, the app lowers each request's output limit by an estimate of the conversation length, and that estimate counted every earlier reasoning block. In long conversations with a lot of reasoning the estimate far exceeded the real length and pushed the output limit close to zero. When the server-reported usage is not available, the app now sends the model's configured output limit; a nearly full context is still handled by automatic compaction.
- Fixed plugin-market updates and uninstalls that could freeze the window on "Updating…" for about 10 minutes, then report a failure and leave the plugin showing "Install" after a restart. The bundled pnpm 11.8.0 has a known defect: after finishing an install or removal its process sometimes never exits. The bundled pnpm is now 11.28.5, fixed on both Windows and macOS.
- When the main model reads an image through the vision model and recognition fails (for example a network blip or a temporary upstream error), it is now retried automatically twice instead of failing the whole turn with "Image recognition failed"; a failed result is no longer held for 60 seconds, so sending again recognizes the image right away (TokensAPI Models 0.2.31).
- Fixed the bottom-left account entry still showing "More" instead of the user name after signing in on the startup sign-in page, until Settings was opened or the app restarted (TokensAPI Account 0.1.14).

### ⚠️ Other Changes

- The first plugin installation after the pnpm upgrade downloads package metadata again, so it may take a little longer than usual.
- The product version is v0.7.19; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Output limit: the request at the point of failure was rebuilt from a user's exported conversation (338 messages, 37 images) and sent to TokensAPI through the model integration code the app uses. Before the fix the request carried an output limit of 1 and the model stopped on length after one token, matching the user's log; after the fix the limit was 32768 and the model answered normally. Five build-code regression tests were added. TokensAPI Account 0.1.14: plugin CI passed on Node 22 and 24; 85 plugin regression cases and 16 real-host contract tests passed; new cases cover both browser sign-in and a manually entered API key. Plugin updates: following the market's real update flow on Connect, pnpm 11.8.0 failed to exit after finishing in 2 of 40 operations, reproducing the freeze, while pnpm 11.28.5 completed all 40. TokensAPI Models 0.2.31: plugin CI passed on Windows, macOS and Linux; 34 real-host contract tests passed; the screenshot from the user report was recognized, and with the network unreachable the read was retried twice before the original message appeared. The overlay registry check found no drift and build-code regression passed 239 tests. Released installers: the Windows installer matches its published SHA-256; unpacked, it contains the files for all four fixes (pnpm 11.28.5, TokensAPI Models 0.2.31, TokensAPI Account 0.1.14, the output-limit correction), and the packaged code yields an output limit of 32768 for the conversation above. The release pipeline's Windows quality gate passed and the macOS installers were signed and notarized. Interface acceptance after installation on real devices has not been performed.

## Known Limitations

Same as v0.7.16: downgrading to 0.5.x loses the display of migrated settings and sessions; session logs are uploaded before each model request, so a turn's last reply is uploaded only with that session's next request; GPT and Codex models are not usable through TokensAPI for now and are hidden from the model list by default.
