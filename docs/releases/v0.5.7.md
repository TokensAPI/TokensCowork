# TokensCowork v0.5.7

修复 Claude 请求身份被 DSH 覆盖后遭上游拒绝的问题，并让会话模型列表完整展示所有可用对话模型、自动匹配适合的请求协议。

## 本次更新

- Claude Anthropic Messages 通过模型管理插件的私有本机回环传输，在最终出网边界设置服务端要求的 Claude CLI 请求身份；仅开放 Messages 与 Token Count 路径，不保存 API Key。
- 会话模型选择器不再被当前协议限制，统一展示 TokensAPI 返回的全部可用对话模型。
- 跨协议切换会先解析并应用模型协议，再刷新 Host 目录并同步当前会话，避免 Claude、GPT 或 Chat 模型短暂走错适配器。
- Claude 默认 Anthropic Messages，GPT/Codex 默认 Responses，其他模型优先恢复已保存协议，否则默认 Chat Completions。
- 模型管理插件升级至 `0.2.21`，固定提交 `64782897b7446ca616bd2b643a6ad9cd118d4fad`。

## 安装说明

退出应用后覆盖安装，无需删除用户配置、API Key 或会话数据。

## 验证结果

- 模型管理插件完整串行测试 914 项通过、61 项按环境跳过、0 项失败。
- TypeScript、Biome Lint、插件构建、版本戳及差异检查通过。
- 使用现有 TokensAPI 凭据和 `claude-opus-5` 完成真实流式请求，返回 HTTP 200 与正常 SSE 事件。
- 新增 Claude 最终线级 User-Agent、回环路径隔离、完整模型目录、跨协议切换顺序和失败回滚测试。
- 安装包及跨平台签名、升级和打包验证以 CI 结果为准。

## 已知限制

- 模型可用性仍取决于用户网络、TokensAPI 服务状态及对应模型权限。
- 无对话协议、纯图片／视频或图片能力尚未完成选择的模型不会出现在会话模型列表中。
