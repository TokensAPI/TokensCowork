## 本次更新

### 🐛 问题修复

- 修复在插件市场更新或卸载插件时，界面可能停在「正在更新…」约 10 分钟、什么都点不了，结束后提示失败，重新打开应用后插件变成「可安装」的问题。原因是应用内置的 pnpm 11.8.0 有一个已知缺陷（pnpm #12297、#9530）：完成安装或卸载后，进程偶尔不会退出，应用只能等到超时。带有其他平台可选依赖的插件（例如连接中心）在第一次更新时最容易遇到。现在内置的 pnpm 升级到 11.28.5，Windows 和 macOS 都已修复。

### ⚠️ 其他变更

- 内置 pnpm 升级后第一次安装插件时，会重新下载一次插件的元数据缓存，速度可能比平时稍慢。
- 产品版本使用 v0.7.17，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### 🐛 Bug Fixes

- Fixed plugin-market updates and uninstalls that could freeze the window on "Updating…" for about 10 minutes, then report a failure and leave the plugin showing "Install" after a restart. The bundled pnpm 11.8.0 has a known defect (pnpm #12297, #9530): after finishing an install or removal its process sometimes never exits, so the app waited for a timeout. Plugins with optional dependencies for other platforms, such as Connect, hit it most often on their first update. The bundled pnpm is now 11.28.5, fixed on both Windows and macOS.

### ⚠️ Other Changes

- The first plugin installation after the pnpm upgrade downloads package metadata again, so it may take a little longer than usual.
- The product version is v0.7.17 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Following the market's real update flow (remove, then install) through the host plugin manager on a profile that already had the plugin installed, Connect was updated back and forth between 2.10.0 and 2.10.1: pnpm 11.8.0 failed to exit after finishing in 2 of 40 operations, reproducing the freeze, while pnpm 11.28.5 completed all 40 operations with the correct plugin versions and manifest. The overlay registry check found no drift, the overlay assembly check found no broken overlays, and build-code regression passed 233 cases. Installation and interface acceptance of the v0.7.17 installers on real devices have not been performed yet.

## Known Limitations

Same as v0.7.16: downgrading to 0.5.x loses the display of migrated settings and sessions; session logs are uploaded before each model request, so a turn's last reply is uploaded only with that session's next request; GPT and Codex models are not usable through TokensAPI for now and are hidden from the model list by default.
