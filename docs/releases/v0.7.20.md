# TokensCowork v0.7.20

在 v0.7.19 基础上，更新提醒不再每次启动都弹窗：只有大版本弹一次，其余版本只在左下角显示可更新；新版本改为分批推送（TokensCowork 更新插件 0.2.0）。同时修复联网搜索的几个工具每次报错，以及模型一次写很长的文件时越来越慢的问题。

## 本次更新

### ✨ 新功能与优化

- 更新提醒不再打扰：发现新版本时，只有大版本（版本号前两位变化，例如 0.7 到 0.8）会弹一次对话框，点「稍后」后同一版本不再弹；其余版本不弹窗、不通知，只在左下角显示下载按钮，托盘菜单同步显示可更新。自己点「检查更新」时照常显示结果。
- 新版本分批推送：应用检查更新时先向 TokensCowork 插件市场服务询问本机可以更新到哪个版本，新版本会先提供给一部分用户，确认稳定后再提供给所有人。自己点「检查更新」不受分批比例限制。市场服务暂时连不上时，仍按原来的方式提供最新稳定版。

### 🐛 问题修复

- 联网搜索的「高级搜索」「平台搜索」和「搜索引擎自检」三个工具每次调用都返回 `content.some is not a function`，现已修复；普通的联网搜索不受影响（联网搜索插件 0.2.5）。
- 打开网页抓取后，`web_fetch` 每次都报「注册了多个可用的网页抓取方式」，现已修复，固定走普通 HTTP 抓取（联网搜索插件 0.2.5）。
- 模型在一次工具调用里写出很长的内容（例如一份很大的 HTML 或报告）时，应用越写越慢、甚至像卡住。原因是每收到一小段就把已收到的全部内容重新解析一遍；现在改为只在这次调用结束时解析一次。本机用 100 KB 的内容测试，这部分耗时从约 21 秒降到约 0.2 秒。
- 插件市场检查插件更新失败时，现在会把原因记入应用日志，便于排查；界面与重试方式不变。

### ⚠️ 其他变更

- 检查更新时，应用会向 TokensCowork 插件市场服务发送：本机安装时随机生成的安装标识（与硬件无关）、当前版本、系统与处理器类型；已登录时附带 API Key，用于识别所属组织。不发送对话内容与文件。
- 从 v0.7.19 及更早版本升级到本版本时，仍会按旧方式弹出更新对话框；装上本版本后，后续版本才按新的提醒方式。
- 产品版本使用 v0.7.20，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### ✨ Features and Improvements

- Quieter update reminders: when a new version is found, only a big version (the first two numbers change, for example 0.7 to 0.8) opens a dialog, once; after "Later" the same version does not prompt again. Other versions open no dialog and send no notification; the download button at the bottom left and the tray menu show that an update is available. Clicking "Check Updates" yourself shows the result as before.
- Staged delivery of new versions: when checking for updates, the app first asks the TokensCowork plugin market service which version this installation may update to. A new version is offered to some users first and to everyone once it is confirmed stable. Clicking "Check Updates" yourself is not limited by the staged percentage. If the market service cannot be reached, the latest stable version is offered as before.

### 🐛 Bug Fixes

- The web search tools "advanced search", "platform search" and the search-engine self-check returned `content.some is not a function` on every call; fixed. Ordinary web search was not affected (Web Search plugin 0.2.5).
- With web fetching turned on, `web_fetch` failed every time with "multiple usable web providers are registered"; fixed, it now always uses plain HTTP fetching (Web Search plugin 0.2.5).
- When the model wrote very long content in a single tool call (for example a large HTML file or report), the app became slower and slower and could appear frozen. Each small chunk caused everything received so far to be parsed again; it is now parsed once when the call ends. With 100 KB of content on a local test, this part dropped from about 21 seconds to about 0.2 seconds.
- When the plugin market fails to check a plugin for updates, the reason is now written to the application log to help diagnosis; the interface and retry behavior are unchanged.

### ⚠️ Other Changes

- When checking for updates, the app sends the TokensCowork plugin market service: an installation ID generated at random on install (unrelated to hardware), the current version, and the operating system and processor type; when signed in, the API Key is attached to identify the organization. No conversation content or files are sent.
- Upgrading to this version from v0.7.19 or earlier still shows the old update dialog; the new reminder behavior applies to versions after this one is installed.
- The product version is v0.7.20 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

TokensCowork Updates plugin 0.2.0: plugin CI passed on Node 22, 24 and 26 (106 cases); 24 real-host contract tests passed, including the installation ID reaching the plugin through the real host and a pre-release named by the service being downloaded and verified. The staged-delivery endpoint of the plugin market service is live, and its rule and management tests passed. Web Search plugin 0.2.5: both problems were reproduced on the current host before the fix; afterwards the real-host contract passed on Node 22 and 24 and all 21 mutation checks hit. Streamed tool arguments: comparing the shipped code before and after the fix, the final arguments are identical and parsing dropped from once per chunk to once per call. The overlay registry check found no drift and build-code regression passed. Installation and interface acceptance of the v0.7.20 installers on real devices have not been performed yet.

## Known Limitations

Same as v0.7.19: downgrading to 0.5.x loses the display of migrated settings and sessions; session logs are uploaded before each model request, so a turn's last reply is uploaded only with that session's next request; GPT and Codex models are not usable through TokensAPI for now and are hidden from the model list by default.
