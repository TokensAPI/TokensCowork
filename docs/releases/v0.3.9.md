# TokensHarness v0.3.9

本预发布版本修复 v0.3.7 与 v0.3.8 在 Windows 安装时报 "Failed to decompress files" 的问题，为构建流程增加同类问题的失败关闭门禁，并暂缓分发尚未验证的连接中心插件。

## 本次更新

### Windows 安装修复

- 修复安装器解压失败：联网搜索插件携带的两个中文文件名辅助脚本随安装包进入 `app-64.zip` 后，NSIS 解压组件（nsisunz.dll）不支持 UTF-8 zip 条目，按 OEM 代码页转换产生非法文件名，导致安装报 "Failed to decompress files / Error opening output file(s)"。相关脚本已改为 ASCII 文件名（`start-deepseek-harness.cmd`、`switch-search-engine.cmd`），内容不变。
- 产物验收新增失败关闭门禁：打包产物中出现任何非 ASCII 文件名即中断构建并指出问题文件，防止同类问题再次流入发布。

### 插件调整

- 移除尚未完成验证的 `tokens-connect-ui` 产品登记和子模块；本版本不随安装包分发，验证通过后再重新引入。
- 飞书连接沿用已验证的 0.2.1 版本；联网搜索、TokensAPI 模型、本地文件引用和版本更新插件保持不变。

## 安装说明

### Windows

1. 下载 Windows amd64 安装器并双击运行。
2. 正常升级会自动卸载旧版本并保留 `%APPDATA%\TokensHarness` 用户数据。
3. 如果旧文件仍被占用，先完全退出 TokensHarness 和托盘进程，再重新运行安装器。
4. 未签名安装器可能出现 SmartScreen 提示，请确认文件来自本仓库官方 Release。

### macOS

1. Apple Silicon 用户下载 `arm64`，Intel 用户下载 `amd64`。
2. 打开 DMG，将 TokensHarness 拖入“应用程序”。
3. 未正式公证的构建首次启动时，需要右键应用并选择“打开”。

## 验证重点

1. 在曾报 "Failed to decompress files" 的环境上，`0.3.9` 安装器能够完整解压并完成安装。
2. 从 v0.3.5 直接运行 `0.3.9` 安装器，能够自动保留数据并完成覆盖升级。
3. 联网搜索插件功能正常，其辅助脚本更名不影响搜索与引擎切换。
4. 安装包内不包含连接中心插件；飞书连接、TokensAPI 模型、本地文件引用和版本更新入口保持正常。

## 验证结果

- 打包产物文件名门禁、卸载命令解析、注册表记录规范化和 NSIS 升级保护均有自动化检查。
- 产品布局、插件依赖许可、Desktop 完整检查和 macOS 双架构构建由本次远程 Action 执行。
- Windows 构建复用最终安装器执行上一稳定版覆盖升级及锁文件恢复 smoke。

## 已知限制

- Windows 安装器暂未进行 Authenticode 签名，可能触发 SmartScreen 提示。
- Windows 文件被其他进程持续占用时，安装器会安全终止，需要关闭占用程序后重试，不会强制结束可能含未保存数据的进程。
- macOS 正式签名与公证取决于仓库是否配置完整的 Apple 发布凭据；否则使用 ad-hoc 签名。
- 当前不提供 Windows ARM64、Windows 32 位或 Linux 安装包。
