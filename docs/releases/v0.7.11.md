# TokensCowork v0.7.11

在 v0.7.10 基础上修复一个会把会话卡死的问题：同一个工具被连续调用三次后，这一轮报错 `format v4 message requires a producer-owned source kind`，之后会话无法继续，导出也失败。内置的「循环护栏」升到 0.1.1。内核版本与 v0.7.10 相同。

## 本次更新

### 🐞 问题修复

- 连续三次相同的工具调用不再卡死会话：「循环护栏」在第三次相同调用时会给模型插入一条提醒，这条提醒用的是内核 0.2 已经不再接受的来源格式，内核拒收后整轮写入失败，会话停在原处，之后每次发消息都报 `format v4 message requires a producer-owned source kind`，导出会话也失败。现在提醒按内核要求标明自己的来源，正常写入；提醒、阻断的次数与规则不变。已经卡住的会话在升级并重启后可以继续。

### ⚠️ 其他变更

- 内置插件更新：「循环护栏」0.1.0 → 0.1.1。其余内置插件与 v0.7.10 相同。
- 插件市场里的「连接中心」同时更新到 2.9.8（不随安装包内置，在插件市场里更新）：带来源信息或回复指引的 IM 消息会以同样的方式卡住会话，2.9.8 已修复，宿主契约检查 47 项通过。
- 产品版本使用 v0.7.11，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### 🐞 Bug Fixes

- Three identical tool calls in a row no longer wedge a session: on the third, the built-in loop guard adds a reminder for the model, and that reminder used a source format the 0.2 core no longer accepts. The core refused it, the whole write of the turn failed, the session stayed where it was, every later message failed with `format v4 message requires a producer-owned source kind`, and exporting the session failed too. The reminder now names its own source as the core requires and is written normally; when it reminds and when it blocks are unchanged. A session that is already stuck continues after upgrading and restarting.

### ⚠️ Other Changes

- Built-in plugin updated: loop guard 0.1.0 to 0.1.1. The other built-ins are unchanged from v0.7.10.
- The market's Connect plugin is updated to 2.9.8 at the same time (not bundled; update it in the plugin market): IM messages carrying source details or reply guidance wedged a session the same way, and 2.9.8 fixes that; its host-contract check passes 47 cases.
- The product version is v0.7.11 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Loop guard 0.1.1: the plugin's own suite passes 21 cases; its session-contract case checks every reminder with the real write check (assertV4RowAdmission) of the host this product assembles, with the old format's refusal as the control, and passes; with the source changed back to the old format both fail. The problem was reproduced on real sessions session-f4ab9c9a (2026-11-04) and session-fec8d160 (2026-11-05). Connect 2.9.8: the plugin's unit suite passes 3077 cases; on the real host this product assembles, `check:host` passes all 47 cases, including two new ones that hand the rewritten messages to the host's real write check. Overlay review: the loop guard overlay's pinned input was rechecked, and `cordis.patch.yml` is unchanged between the two versions. For the CI Windows quality gate, see the build run. Installation and interface acceptance of the v0.7.11 installers on real devices have not been performed yet.

## Known Limitations

Same as v0.7.10: downgrading to 0.5.x loses the display of migrated settings and sessions; a failed route save after a model pick reverts the button and logs the reason without a toast; the first open of the market Discover still takes about 1–2 seconds; English release notes in the dialog show highlights but no summary; a very long highlight shows only the whole sentences that fit; session logs are uploaded before each model request, so a turn's last reply is uploaded only with that session's next request.
