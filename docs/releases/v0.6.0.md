# TokensCowork v0.6.0

将 Desktop 内核升级到 v2.0.17，并跟随其固定的 DSH 0.2.0-rc.2；适配新版市场持久化、首次启动流程和 Windows 沙箱执行接口，保留 TokensCowork 自营插件源与产品默认配置。

## 本次更新

### ✨ 新增功能

- 侧栏左下角的账号菜单改为 TokensAPI 账号：已登录时显示账号名称与头像，可进入设置或退出登录；未登录时可直接发起 TokensAPI 登录。
- 新增侧栏“插件”页（DSH 0.2 原生），集中查看官方与已安装插件，并可启用、配置或卸载；插件安装统一通过插件市场。
- 来自上游 Desktop：恢复模式下可以停用出问题的插件而不必卸载；后台网络请求跟随系统代理；启动时可直接以指定文件夹作为工作区打开。

### 🐛 问题修复

- 修复在设置中切换插件市场后，下次启动报错“preferences must contain exactly the supported fields”而无法进入应用的问题；启动时会正常切回 TokensAPI 插件市场。
- 英文界面下，登录与 API Key 验证失败的提示改为英文显示。
- 输入框的模型列表与设置页一致，显示 TokensAPI 返回的全部模型，选中即可使用；修复选择 Claude 等其他协议的模型时报“session/model-unavailable”的问题。
- 修复模型设置（图片处理方式、视觉模型、接口地址、备用线路）重启后恢复默认的问题。
- 联网搜索适配新版设置接口，引擎不可用时自动切换。
- 来自上游 Desktop：D 盘等非系统盘上的工作区可以正常进入 Windows 沙箱；Windows 打开本地路径时资源管理器不再被遮挡；完善 macOS 麦克风与录音权限。

### 🎨 体验优化

- 移除侧栏“更多”菜单中指向上游官方渠道的“意见反馈”，设置中不再显示 DeepSeek 官方账号页，账号统一在“TokensAPI 账户”中管理。
- 侧栏左下角已登录的账号行与上方“插件市场”对齐。
- 在输入框切换模型时立即生效、不再卡顿，切换协议在后台完成；切换后立即发送的消息会等新协议就绪再发出。

### ⚠️ 其他变更

- Desktop 从 v2.0.9 升级到上游稳定标签 v2.0.17，固定提交 `838ba60fd79362087c0a0d134efee671c284786a`。
- DSH 从 0.1.5-rc.2 升级到 Desktop 所用的 0.2.0-rc.2，固定提交 `639ed015397290b3745d163aafe02ffee4aa3f84`。
- 市场来源改为新版存储接口，在初始内存状态和持久化存储接管后均修复产品固定源；继续使用 TokensAPI 自营目录、账户授权及私有 Registry。
- 适配页面级首次启动引导，继续使用产品预置配置；适配统一的 Windows shell execution 接口，保留 ACL 启动控制台与基础设施失败熔断。
- 保留原有产品更新入口、托盘品牌、主题覆盖及六个固定插件；TokensAPI 账户升级到 0.1.11，TokensAPI 模型升级到 0.2.24，联网搜索升级到 0.2.1，其余插件版本与 v0.5.25 相同（Tokens Cowork UI 0.2.24）。
- 与官方 DSH 共用 `desktop` Profile 时，Profile 中更新一代的 DSH 运行时包不会替换应用内置运行时，避免启动进入恢复模式；市场插件更新不受影响。
- **升级后数据格式随之更新：** 首次启动会把设置迁移到 DSH 0.2 的存储格式，并将打开过的会话写为新格式。升级后不支持回退到 0.5.x：回退版本将读不到迁移后的模型配置、主题、语言和市场记录，也不显示已升级的会话。原设置备份为 `~/.dsh/settings.yaml.imported`。
- 产品版本使用 v0.6.0，发布时设置 GitHub Pre-release 标记。

## 已知限制

- DSH 跨越 0.1 到 0.2 接口，固定插件的真实宿主行为仍需验收。
- 通过 TokensAPI 使用 gpt 系列模型时，上游渠道目前只接受 Codex 客户端，发送消息会失败（界面显示为 “API key is invalid”）；待 TokensAPI 侧调整后恢复，其他模型不受影响。
- 部分插件市场插件需更新到兼容 DSH 0.2 的版本后才能在 0.6 上启用；旧版本会被自动停用，在插件市场更新即可。
- 升级会迁移设置与会话格式，降级回 0.5.x 会丢失这部分设置和会话的显示。
- 保留自营市场与现有产品覆盖；上游其他新增能力未逐项执行真实用户交互验收。
- macOS 签名、公证和 Windows 覆盖安装需在对应平台发布流程完成。

## What's New

### ✨ New Features

- The sidebar account menu now uses the TokensAPI account: when signed in it shows the account name and avatar with Settings and Sign out; when signed out it starts TokensAPI sign-in directly.
- A new sidebar "Plugins" page (native to DSH 0.2) lists official and installed plugins and lets you enable, configure or uninstall them; plugins are installed through the plugin market.
- From upstream Desktop: Recovery Mode can disable a failing plugin without uninstalling it; background network requests follow the system proxy; a folder named at launch opens as a workspace.

### 🐛 Bug Fixes

- Fixed startup failing with "preferences must contain exactly the supported fields" after switching the plugin market in Settings; startup now switches back to the TokensAPI plugin market normally.
- Sign-in and API key verification errors are now shown in English when the interface language is English.
- The composer model list now matches Settings and shows every model returned by TokensAPI, ready to use when selected; fixed "session/model-unavailable" when choosing Claude and other models that use a different protocol.
- Fixed model settings (image handling, vision model, endpoint, fallback route) reverting to defaults after a restart.
- Web search adapts to the new settings API and switches engines automatically when one is unavailable.
- From upstream Desktop: workspaces on non-system drives such as D: can enter the Windows sandbox; File Explorer is no longer hidden when opening local paths; macOS microphone and recording permissions are completed.

### 🎨 Improvements

- Removed the "Feedback" entry that pointed to the upstream official channel from the sidebar More menu, and Settings no longer shows the DeepSeek official account page; accounts are managed in "TokensAPI Account".
- The signed-in account row at the bottom of the sidebar now lines up with "Plugin Market" above it.
- Switching models in the composer takes effect immediately without stalling; the protocol switch completes in the background, and a message sent right away waits until the new protocol is ready.

### ⚠️ Other Changes

- Upgrade Desktop v2.0.9 to the stable upstream tag v2.0.17 and use its pinned DSH 0.2.0-rc.2.
- Adapt market persistence, page onboarding and unified Windows shell execution while retaining the TokensAPI catalog, authorization, private Registry, product defaults and ACL infrastructure fuse.
- Keep all six product plugins; TokensAPI Account moves to 0.1.11, TokensAPI Models to 0.2.24 and Web Search to 0.2.1; the others match v0.5.25 (Tokens Cowork UI 0.2.24). Mark v0.6.0 as a GitHub Pre-release when publishing.
- When the `desktop` Profile is shared with the official DSH, a newer-series DSH runtime package in that Profile no longer replaces the bundled runtime, avoiding a Recovery Mode startup. Plugin-market updates are unaffected.
- **Data formats are upgraded:** the first launch migrates settings to the DSH 0.2 storage format and writes opened sessions in the new format. Downgrading to 0.5.x afterwards is not supported: it cannot read the migrated model configuration, theme, language and market records, and does not list upgraded sessions. The original settings are kept as `~/.dsh/settings.yaml.imported`.

## Verification

Pinned inputs, working-tree layout and build-code regression checks passed. Immutable installation, all six plugin entry imports, Fabric checks, Market build/types (317 passed, 9 product-policy skips), Desktop build/declarations/types, licenses, runtime closure, CLI, Loader, Profile HMR and branding checks passed. ## Known Limitations

DSH moves from the 0.1 to the 0.2 API. Real-host plugin behavior and platform installation, signing and notarization still require verification. Upgrading migrates settings and session formats; downgrading to 0.5.x loses the display of those settings and sessions. GPT models via TokensAPI currently fail to send because the upstream channel only accepts the Codex client (shown as "API key is invalid"); other models are unaffected. Some plugin-market plugins must be updated to DSH 0.2-compatible versions before they can be enabled on 0.6; older versions are disabled automatically and can be updated from the plugin market.
