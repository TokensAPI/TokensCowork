# TokensCowork v0.7.7

在 v0.7.6 基础上更新界面插件「Tokens Cowork UI」到 0.2.27：自动化并入内核自带的计划任务页，顶部与左侧导航共用同一份页面状态，主题改为按 API Key 所属组织自动应用。首次启动会把旧的自动化任务自动迁移过去。内核版本与 v0.7.6 相同。

## 本次更新

### ✨ 新增功能

- 主题按当前 API Key 所属组织自动应用，不再需要手动选择：组织 ID 为 3 时使用 ELECTRO X 主题，其余组织、个人 Key、未配置 Key 或查询失败时使用基础主题。Key 切换后重新查询，查询期间保留当前主题，结果明确后才切换。Key 不会发送给客户端，组织查询结果不写入磁盘，查询失败对同一 Key 冷却 30 秒。设置中不再提供主题选择，旧的本地主题选择记录不再生效。

### 🐛 问题修复

- 模型自我介绍时会说出上游品牌，例如"运行在 TokensCowork（DeepSeek Harness Web GUI）里，由 DeepSeek Harness 承载"。原因是内核 0.2.1 新增了一个面向 harness 开发者的提示词插件，它自己往系统提示词里写入写死的上游品牌与本机 harness 路径，产品原有的身份行覆盖管不到它。本产品不开发 harness 本身，现已整条停用。

### 🎨 体验优化

- 自动化改用内核自带的计划任务：导航里的「自动化」直接打开内核的 schedules 页面，新任务统一使用内核原生的 schedule 工具并在原会话接收定时指令。插件不再自带独立的自动化页面、工具与调度器。
- 顶部与左侧导航共用同一份页面选择状态，两边切换互相同步，布局交给内核管理。内核较旧、没有该导航接口时自动退回原有的兼容路径。

### ⚠️ 其他变更

- 首次启动会自动迁移旧的自动化任务（读取 `~/.dsh/tokens-automation/ledger-v1.json` 里处于启用状态的任务）：优先沿用原会话；原会话不存在、已归档、属于子代理、需要格式升级或工作目录不匹配时，新建一个持久化的专用会话承接。每天、每周、每月的计划使用迁移时的宿主时区，每周与每月从旧的下次执行时间推导日期；已过期的一次性任务在迁移后约一分钟补执行。逐项结果写入 `.migration.json`。
- 内置插件更新：「Tokens Cowork UI」0.2.24 → 0.2.27。其余内置插件与 v0.7.6 相同。
- 产品版本使用 v0.7.7，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### ✨ New Features

- The theme now follows the organization behind the current API key instead of a manual choice: organization 3 gets the ELECTRO X theme, and every other organization, a personal key, a missing key or a failed lookup gets the base theme. Switching keys triggers a new lookup, the current theme stays while it runs, and the switch happens only once the result is known. The key is never sent to the client, lookup results are not written to disk, and a failed lookup backs off for 30 seconds for that key. Theme selection is gone from settings and any previously stored local choice no longer applies.

### 🐛 Bug Fixes

- The model introduced itself with upstream branding, for example "running inside TokensCowork (the DeepSeek Harness Web GUI), hosted by DeepSeek Harness". Core 0.2.1 added a prompt plugin aimed at people who develop the harness itself, and it writes hard-coded upstream branding and the local harness checkout path into the system prompt, which the product's existing identity override does not reach. This product does not develop the harness, so that plugin is now disabled outright.

### 🎨 Improvements

- Automations now use the core's own scheduled tasks: "Automation" in the navigation opens the core's schedules page, and new tasks use the core's native schedule tools and receive their timed instructions in the original session. The plugin no longer ships its own automation page, tools or scheduler.
- The top and left navigation share one page-selection state, so switching in either place keeps the other in step, and the layout is managed by the core. On an older core without that navigation interface the previous compatibility path is used.

### ⚠️ Other Changes

- On first launch the enabled tasks in the old ledger (`~/.dsh/tokens-automation/ledger-v1.json`) are migrated automatically. The original session is reused where possible; when it is missing, archived, owned by a subagent, in need of a format upgrade or pointing at a different working directory, a dedicated persistent session takes over. Daily, weekly and monthly schedules use the host timezone at migration time, weekly and monthly dates are derived from the old next-run time, and an overdue one-off task runs about a minute after the migration. Each outcome is written to `.migration.json`.
- Built-in plugin updated: "Tokens Cowork UI" 0.2.24 to 0.2.27. The other built-ins are unchanged from v0.7.6.
- The product version is v0.7.7 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Plugin artifact: the measured SHA-256 of the 0.2.27 tarball matches the one declared in its release manifest, and the minimum core it declares (0.2.1-rc.2) is the one this product ships. VERIFY_GATE_LINE_EN The automation migration and the organization themes are covered by the plugin's own suite; this product did not run an end-to-end check with a real organization key or against existing automation tasks, so check `.migration.json` after the first launch. ## Known Limitations

Same as v0.7.6: GPT models via TokensAPI currently fail to send because the upstream channel only accepts the Codex client; visual acceptance of the Discover home is pending; downgrading to 0.5.x loses the display of migrated settings and sessions; a failed route save after a model pick reverts the button and logs the reason without a toast; the first open of the market Discover still takes about 1–2 seconds; English release notes in the dialog show highlights but no summary; a very long highlight shows only the whole sentences that fit. The automation migration covers only the enabled tasks in the old ledger and runs once; after it the old execution path no longer runs, and downgrading to v0.7.6 does not migrate the tasks back. No product overlay is bound to the interface plugin, so the overlay doctor does not ask for a re-check when it is upgraded; assembly and interface acceptance have to catch problems instead.
