# TokensCowork v0.7.3

在 v0.7.2 基础上的维护版：插件市场"发现"页先显示缓存目录、远程请求快速失败，不再因一条挂起的连接转几十秒；"TokensAPI 模型"在 API Key 由登录等途径写入时即时刷新自己的模型列表与路由，视觉适配层改为继承内核基类；"联网搜索"收窄内核兼容声明并固化真实内核契约用例。内核版本与 v0.7.2 相同。

## 本次更新

### 🐛 问题修复

- 插件市场"发现"页：目录扫描按来源串行，一条挂起的远程连接会让所有打开请求排队几十秒，直到超时才一起放行。现在有快照时先立即返回上次目录（标记为过期）再后台刷新，刷新失败保留旧内容并提供重试；产品来源的远程请求 8 秒内快速失败并释放队列；来源清单按产品源缓存 24 小时，首次打开从两跳远程请求减为一跳。
- "TokensAPI 模型"升到 0.2.26：API Key 由本插件设置页以外的途径写入时（如 TokensAPI 账户登录），插件自己的主/视觉模型列表与 TokensAPI 路由同步也会立即刷新，不再等待设置页或重启；通用发现路径下的路由在 Key 生效后也会被接管（0.7 起未解析 Key 的路由不再公布任何模型）。
- "联网搜索"升到 0.2.2：内核兼容声明收窄为双端区间并标记可选，DSH 0.3 不再被误放行；DSH 0.2 设置链路（易变配置派生表单、保存落盘、回环桥接、密钥脱敏）与内核评估器判定固化为依赖真实内核的常驻用例。

### ⚠️ 其他变更

- "TokensAPI 模型"的视觉适配层改为继承内核 `LlmAdapter` 基类，内核后续新增的适配器方法自动继承默认实现。
- 市场插件同步更新（通过插件市场获取，不随安装包）：连接中心 2.9.6 新增内核总线事件与流式契约检查；工具按需加载 0.2.7 把内核兼容声明改为双端区间并标记可选。浏览器操作插件已从市场下架（上游已原生支持浏览器操作）。
- 产品版本使用 v0.7.3，发布时设置 GitHub Pre-release 标记；升级与降级说明与 v0.7.0 相同，仍不支持回退到 0.5.x。

## What's New

### 🐛 Bug Fixes

- Plugin market Discover: catalog scans are serialized per source, so one hung remote connection queued every open for tens of seconds until it timed out. When a snapshot exists the last catalog is now returned immediately (marked stale) and refreshed in the background, a failed refresh keeps the old content with a retry; remote requests to the product source fail fast within 8 seconds and release the queue; the source manifest is cached for 24 hours, cutting the first open from two remote hops to one.
- "TokensAPI Models" 0.2.26: when the API key is stored by something other than this plugin's settings page (for example the TokensAPI sign-in), the plugin's own main/vision model lists and the TokensAPI route sync refresh immediately instead of waiting for the settings page or a restart; a route discovered through the generic path is taken over once a stored key makes it answer (since 0.7 a route whose key does not resolve advertises no models).
- "Web Search" 0.2.2: the core compatibility declaration is narrowed to a two-sided optional range so DSH 0.3 is no longer silently accepted; the DSH 0.2 settings path (volatile-config forms, persisted updates, loopback bridge, secret redaction) and the core evaluator verdicts are now resident real-core test cases.

### ⚠️ Other Changes

- The "TokensAPI Models" vision adapter now extends the core `LlmAdapter` base class, inheriting default implementations of adapter methods the core adds later.
- Market plugins updated alongside (obtained from the plugin market, not bundled): Connect Hub 2.9.6 adds core bus-event and streaming contract checks; Progressive Tools 0.2.7 declares two-sided optional core peers. The Browser Use plugin has been withdrawn from the market (upstream now supports browser use natively).
- The product version is v0.7.3 and is marked as a GitHub Pre-release; upgrade and downgrade notes are unchanged from v0.7.0, and downgrading to 0.5.x is still unsupported.

## Verification

Market Discover: four new overlays fail the build when their anchors drift; the staged real routes measured `/state` 35 ms, first open 1.1–2.0 s, cache hit 3–10 ms, stale snapshot 3 ms, forced refresh 0.6 s; with the remote hung, a snapshot is returned in 5 ms and a forced refresh ends by timeout within 8 s; the market client typecheck and 349 vitest cases passed. "TokensAPI Models" 0.2.26: credential-event refresh and adapter-base contract cases passed 7/7 on each of the three real core lines (0.2.1-rc.2, 0.2.0-rc.2, 0.1.5-rc.2), the T0041 composer model-menu comparison passed 6/6, and lint / typecheck / 942 tests / build passed. "Web Search" 0.2.2: 82/82 on the real 0.2.1-rc.2 core including two newly resident core contract cases; the core evaluator accepts 0.1.5 / 0.2.0 / 0.2.1 and rejects 0.3.0-rc.1. Overlay doctor: 81 overlays effective, none broken, none obsolete; build-code regression 163 cases passed. The full product gate (`build.mjs check`) passed all 19 steps (assembly, immutable install, runtime patches, compaction and RPC smoke, plugin compilation and pruning, licenses, Fabric/Market checks, configuration, Desktop build, typecheck, closure/CLI/Loader/Profile verification, branding gate). Installation and functional acceptance of the v0.7.3 installers on real devices have not been performed yet.

## Known Limitations

Same as v0.7.2: GPT models via TokensAPI currently fail to send because the upstream channel only accepts the Codex client; the market's uninstall-then-install update has not been verified on a real device; visual acceptance of the Discover home is pending; downgrading to 0.5.x loses the display of migrated settings and sessions; a failed route save after a model pick reverts the button and logs the reason without a toast. The first open of the market Discover still takes about 1–2 seconds (the process's first connection to the market), later opens are instant; when no catalog has ever loaded and two Discover views are opened at once, the second still waits for the first to finish or time out.
