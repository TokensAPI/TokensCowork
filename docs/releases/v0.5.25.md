## 本次更新

### 🐛 问题修复

- 修复启动进入恢复模式、提示 `profile bundle "@deepseek-ai/dsh-web-app" declares no dsh.bundle in its package.json` 的问题。原先查找 Profile 插件包时会沿上层目录查找，与官方 DSH 等程序共用 `~/.dsh` 时，会误用其留在 `~/.dsh/profiles/node_modules` 等位置的新版运行时包，而当前版本无法加载这类包。现在只采用当前 Profile 自己目录下的包；DSH 运行时包在 Profile 中的副本与应用内置运行时不属于同一版本系列时，使用应用内置版本，正常启动。插件市场安装或更新的其他插件仍按新版本生效。

## What's New

Fixes TokensCowork opening Recovery Mode at startup with "declares no dsh.bundle" when another program using a newer DSH runtime is installed on the same computer.

### 🐛 Bug Fixes

- Fixed startup entering Recovery Mode with `profile bundle "@deepseek-ai/dsh-web-app" declares no dsh.bundle in its package.json`. Profile packages were previously also looked up in parent directories, so when `~/.dsh` was shared with the official DSH or similar programs, a newer runtime package they left in `~/.dsh/profiles/node_modules` or similar locations was used, and this version cannot load it. Only packages inside the active Profile's own directory are now used, and a DSH runtime package in the Profile from a different release series than the bundled runtime is ignored in favor of the bundled version, so the app starts normally. Other plugins installed or updated from the plugin market still take effect with their newer versions.

## Installation

### Windows Installation

1. Download the Windows amd64 installer and fully quit TokensCowork.
2. Run the installer and follow its instructions.
3. The Windows installer is not Authenticode-signed and may trigger SmartScreen. Verify that it came from this repository's release.

### macOS Installation

1. Check your processor in About This Mac and select the Apple Silicon or Intel installer.
2. Fully quit TokensCowork, open the DMG, and drag the application into Applications.
3. Open TokensCowork from Applications. If the first-launch confirmation appears, click Open.

Both macOS packages are published after Developer ID signing and Apple notarization. Install them using the steps above.

## Known Limitations

- TokensCowork and the official DSH still share the `~/.dsh` directory and the Profile named `desktop`. This release prevents the startup failure, but plugins and settings installed into that shared Profile by either program remain visible to both.
